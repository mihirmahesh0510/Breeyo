# Phase 2 -- UI Design Contract

> Visual and interaction contract for the Breeyo design system. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase establishes the design foundation consumed by ALL subsequent feature phases (3-10). Every token, component variant, and interaction pattern declared here becomes the single source of truth.
>
> **Update 2026-04-17:** Added Owner Portal design contract (OWN-01 to OWN-06). The portal is a lightweight, mobile-responsive web surface accessed via tokenised magic links sent through WhatsApp. It shares the Breeyo design system but has its own navigation, component, and copywriting requirements distinct from the clinic-facing mobile app.

### Owner Portal Platform Notes

The owner portal is a **Next.js page** (built in Phase 9, designed in Phase 2) that shares the Breeyo design token system but runs as standard HTML/CSS/JS -- not React Native. Key distinctions:

| Aspect | Mobile App | Owner Portal |
|--------|-----------|--------------|
| Runtime | React Native (Expo) | Next.js (browser) |
| Styling | React Native StyleSheet | Tailwind CSS using design tokens as CSS vars |
| Components | React Native Paper | HTML elements styled with Tailwind + shared token values |
| Font | System (Roboto/SF Pro) | Inter (variable, subset to Latin + Devanagari) |
| Navigation | Bottom tab bar + stack | Single-page scroll with sticky header |
| Authentication | Email/OTP session | Tokenised magic link (no login) |
| Data scope | Full clinic data (RBAC) | Owner's pets and invoices only (OWN-06) |

Token bridge: The same `colors.ts`, `spacing.ts`, `typography.ts` source files generate both React Native theme objects AND CSS custom property declarations via a build script. One source of truth, two output formats.

## Spacing Scale

Base unit: 8px (CONTEXT D-04). All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| `spacing.xxs` | 2px | Hairline separators, icon badge offset |
| `spacing.xs` | 4px | Icon-to-label gap, inline padding |
| `spacing.sm` | 8px | Compact element spacing, chip padding |
| `spacing.md` | 16px | Default element spacing, card internal padding |
| `spacing.lg` | 24px | Section padding, form field gaps |
| `spacing.xl` | 32px | Layout gaps between sections |
| `spacing.2xl` | 40px | Major section breaks |
| `spacing.3xl` | 48px | Bottom tab bar height padding zone |
| `spacing.4xl` | 56px | Large section dividers |
| `spacing.5xl` | 64px | Page-level spacing, safe area compensation |

Exceptions:
- **Touch targets**: 44x44pt minimum (CONTEXT D-28). Padding expands hit area when visual element is smaller.
- **Bottom tab bar height**: 56px visible + 8px safe area = 64px total reserved zone.
- **FAB size**: 56px diameter (M3 standard), positioned 16px from bottom-right edge above tab bar.
- **Status bar safe area**: Platform-dependent (Android ~24px, iOS ~44px notch). Use `useSafeAreaInsets()`.
- **Owner portal sticky header**: 56px height. No tab bar -- portal uses vertical scroll only.
- **Owner portal content max-width**: 480px centered. Prevents line lengths from exceeding ~75 characters on wider screens.

## Typography

Font family: System default (Roboto/SF Pro) for mobile; Inter for web portal. Following Material Design 3 type scale, adapted to 7 declared roles (CONTEXT D-03).

| Role | M3 Token | Size | Weight | Line Height | Letter Spacing | Usage |
|------|----------|------|--------|-------------|----------------|-------|
| Display | `displayMedium` | 45px | 400 | 52px (1.16) | 0 | Splash/onboarding hero text only |
| Heading 1 | `headlineLarge` | 32px | 400 | 40px (1.25) | 0 | Screen titles (e.g. "Walk-in Queue") |
| Heading 2 | `headlineMedium` | 28px | 400 | 36px (1.29) | 0 | Section headers within a screen |
| Subheading | `titleMedium` | 16px | 500 | 24px (1.5) | +0.15px | Card titles, list group headers, nav bar title |
| Body | `bodyLarge` | 16px | 400 | 24px (1.5) | +0.5px | Primary body text, form labels, descriptions |
| Caption | `bodySmall` | 12px | 400 | 16px (1.33) | +0.4px | Timestamps, helper text, secondary metadata |
| Overline | `labelSmall` | 11px | 500 | 16px (1.45) | +0.5px | Status badges, section labels, all-caps tags |

Weights used: **Regular (400)** and **Medium (500)** only.
- 400: Body text, headings, captions
- 500: Subheadings, overlines, button labels, emphasis within body

No bold (700) in the system. Medium (500) serves as the emphasis weight. This keeps the type palette lean and prevents visual noise on small screens.

### Owner Portal Typography Mapping

The portal uses a reduced subset of the full type scale. Only 4 roles are needed for the simpler portal UI.

| Portal Element | Maps To | Size (Inter) | Weight | Usage |
|---------------|---------|-------------|--------|-------|
| Clinic name / pet name header | Heading 2 | 28px | 400 | Top of portal, pet profile header |
| Section title | Subheading | 16px | 500 | "Medical History", "Invoices", "Pay Now" |
| Body text | Body | 16px | 400 | Diagnosis text, prescription details, invoice line items |
| Metadata | Caption | 12px | 400 | Visit dates, invoice numbers, amounts, status labels |

The portal does NOT use Display or Heading 1 -- the interface is too compact for those scales. Heading 2 (28px) is the largest text on any portal screen.

### Accent Reserved For (exhaustive list)

The 10% accent colors (`primary`, `tertiary`, `error`) are ONLY used on these elements:

1. **Primary (#2E7D32):** Filled buttons (CTA), FAB, active bottom tab icon, links/tappable text, toggle/switch ON state, progress indicators, selected radio/checkbox, portal "Pay Now" button, portal clinic branding accent bar
2. **Tertiary (#E65100):** Notification badge dots, queue position numbers, urgent status badges ("In Consult"), low-stock alert icons, expiry warning icons, portal "Overdue" invoice badge
3. **Error (#BA1A1A):** Destructive button text, error validation borders, error inline messages, "No Show" status badge, delete confirmation icon, portal expired link error icon

Accent is NEVER used for: body text, card backgrounds, screen backgrounds, dividers, borders, placeholder text, or decorative elements.

### Owner Portal Color Notes

The portal uses the identical color palette as the mobile app. No portal-specific colors are introduced. This ensures that when a pet owner sees the portal, it feels like the same brand as any Breeyo-powered communication they receive via WhatsApp.

Portal-specific accent usage:
- **"Pay Now" button**: `primary` filled button -- the single primary CTA on the invoice screen
- **"Overdue" badge on invoice**: `tertiary` background with `onTertiary` text
- **"Paid" badge on invoice**: `primaryContainer` background with `onPrimaryContainer` text
- **Expired link icon/banner**: `error` color for icon, `errorContainer` for banner background

## Elevation System

Using M3 tonal elevation (surface tint overlay) rather than drop shadows on mobile. React Native Paper v5 implements this natively.

| Level | Surface Tint Opacity | Shadow (Android) | Usage |
|-------|---------------------|-------------------|-------|
| 0 | 0% | none | Flat content, list items, screen background |
| 1 | 5% | `0px 1px 2px rgba(0,0,0,0.3), 0px 1px 3px rgba(0,0,0,0.15)` | Cards, text inputs, navigation bar |
| 2 | 8% | `0px 1px 2px rgba(0,0,0,0.3), 0px 2px 6px rgba(0,0,0,0.15)` | Bottom sheet (resting), dropdown menus |
| 3 | 11% | `0px 1px 3px rgba(0,0,0,0.3), 0px 4px 8px rgba(0,0,0,0.15)` | FAB, bottom sheet (expanded), snackbar |
| 4 | 12% | `0px 2px 3px rgba(0,0,0,0.3), 0px 6px 10px rgba(0,0,0,0.15)` | Modal, dialog |
| 5 | 14% | `0px 4px 4px rgba(0,0,0,0.3), 0px 8px 12px rgba(0,0,0,0.15)` | Tooltip (rare) |

### Owner Portal Elevation

The portal uses CSS `box-shadow` equivalents instead of tonal elevation (browser does not support surface tint natively). Only 2 levels are used on the portal:

| Level | CSS box-shadow | Usage |
|-------|---------------|-------|
| Portal 0 | none | Page background, section content |
| Portal 1 | `0px 1px 3px rgba(0,0,0,0.12), 0px 1px 2px rgba(0,0,0,0.08)` | Sticky header, section cards (EMR card, invoice card) |

Minimal elevation keeps the portal lightweight and fast-loading (OWN-05).

## Animation & Motion

Optimized for mid-range Android 8+ (CONTEXT D-10). Functional motion only -- no decorative animations.

| Pattern | Duration | Easing | Usage |
|---------|----------|--------|-------|
| Micro feedback | 100ms | `Easing.out(Easing.ease)` | Button press scale (0.97), toggle flick |
| Expand/collapse | 200ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Accordion open, bottom sheet snap, card expand |
| Screen transition | 250ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Stack navigation push/pop (React Navigation default) |
| Toast enter/exit | 150ms in, 100ms out | `Easing.out(Easing.ease)` | Snackbar slide up, auto-dismiss fade |
| Skeleton shimmer | 1500ms loop | `linear` | Loading skeleton shimmer animation |
| Status badge update | 300ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Queue card status change (pulse + color transition) |

Rules:
- All animations use `useNativeDriver: true` where possible (transforms and opacity only).
- No animation exceeds 300ms except shimmer loops.
- `prefers-reduced-motion` respected: all transitions snap to final state instantly.
- Lottie animations NOT used for Beta. All motion is CSS/RN Animated API only.

### Owner Portal Motion

The portal uses CSS transitions only. Minimal motion to meet the 3-second FCP target (OWN-05).

| Pattern | Duration | CSS Easing | Usage |
|---------|----------|-----------|-------|
| Skeleton shimmer | 1500ms loop | `linear` | Loading placeholder for EMR and invoice cards |
| Section expand | 200ms | `ease-out` | Accordion expand for visit detail within EMR history |
| Payment status update | 300ms | `ease-in-out` | Invoice badge transition from "Unpaid" to "Processing" to "Paid" |
| Page fade-in | 150ms | `ease-out` | Initial content reveal after magic link validation |

No JavaScript-driven animations on the portal. CSS `transition` and `@keyframes` only.

## Gesture Patterns

Universally understood gestures only (CONTEXT D-26). All gesture actions have visible button alternatives.

| Gesture | Action | Visible Affordance | Where Used |
|---------|--------|-------------------|------------|
| Tap | Primary interaction | All interactive elements have visual feedback (ripple) | Everywhere |
| Long press | Context menu / select | Visual hint after 200ms (subtle scale) | List items (patient, inventory) |
| Swipe right | Mark as done / archive | Revealed green background + checkmark icon | Queue cards only |
| Swipe left | Cancel / no-show | Revealed red background + X icon | Queue cards only |
| Pull to refresh | Refresh data | Pull indicator at top | List screens (queue, patients, inventory) |
| Swipe from left edge | Navigate back | System-provided (iOS gesture, Android optional) | All screens via React Navigation |

Gestures NOT used: pinch-to-zoom, two-finger swipe, 3D touch/haptic press, drag-to-reorder (use explicit "reorder" button if needed).

### Owner Portal Gestures

The portal is a standard web page -- no custom gesture handlers. Interaction is tap/click only.

| Interaction | Action | Where Used |
|-------------|--------|------------|
| Tap/click | Open accordion, navigate, initiate payment | All portal interactive elements |
| Native scroll | Scroll through content | Entire portal page |
| Browser back | Return to previous section | Portal uses `history.pushState` for section navigation |

No swipe gestures, no pull-to-refresh, no long press on the portal. This ensures compatibility with all mobile browsers and avoids JavaScript gesture library overhead.

## Navigation Structure

### Mobile App: Bottom Tab Bar

Bottom tab bar as primary navigation (CONTEXT D-25). Stack navigation within each tab (CONTEXT D-27).

| Tab | Icon | Label | Landing Screen |
|-----|------|-------|---------------|
| Queue | `clipboard-list-outline` | Queue | Walk-in queue status board |
| Patients | `paw` | Patients | Patient search/list |
| Inventory | `package-variant-closed` | Inventory | Stock list with search |
| More | `dots-horizontal` | More | Settings, staff, billing, reports menu |

- Active tab: `primary` (#2E7D32) icon + label
- Inactive tab: `onSurfaceVariant` (#49454F) icon + label
- Tab bar background: `surface` (#FFFBF5) with elevation level 2
- Tab bar height: 56px + safe area inset
- Icon size: 24px
- Label size: 12px (labelSmall)

### FAB Placement

| Screen | FAB Label | FAB Action |
|--------|-----------|------------|
| Queue | "Check In" | Opens 2-tap check-in flow |
| Patients | "Add Patient" | Opens patient registration |
| Inventory | "Add Item" | Opens inventory item form |

FAB specs: 56px diameter, elevation level 3, `primary` background, `onPrimary` icon. Positioned 16px from right edge, 16px above tab bar.

### Owner Portal: Single-Page Scroll Navigation

The portal has NO tab bar, NO bottom navigation, NO hamburger menu. It is a single vertically-scrolling page with a sticky header and content sections.

**Portal Layout Structure:**

```
+------------------------------------------+
| [Breeyo logo]  [Clinic Name]     [Lang]  |  <- Sticky header (56px)
+------------------------------------------+
| [Pet avatar]  [Pet Name]                  |  <- Pet profile hero
| [Species] [Breed] [Age]                   |
+------------------------------------------+
| [Medical History]            [expand all] |  <- Section: EMR
|   [Visit 1 - 12 Mar 2026]      [v]       |     Accordion items
|     Diagnosis: ...                        |     (collapsed by default)
|     Prescriptions: ...                    |
|   [Visit 2 - 28 Feb 2026]      [v]       |
+------------------------------------------+
| [Invoices]                                |  <- Section: Invoices
|   [INV-0042 - Rs 1,200]   [Paid]         |     Card per invoice
|   [INV-0051 - Rs 800]     [Pay Now]      |     "Pay Now" = primary CTA
+------------------------------------------+
| [Powered by Breeyo]                       |  <- Footer
| [Request new link]                        |     Link refresh action
+------------------------------------------+
```

**Portal navigation rules:**
- No client-side routing. Single HTML page with anchor-scrollable sections.
- Sticky header remains visible during scroll. Contains clinic branding (name, optional logo) to build trust (OWN-01).
- Language toggle (EN/HI) in header -- visible but not prominent (Caption size, `onSurfaceVariant` color).
- "Pay Now" button within each unpaid invoice card -- the only primary CTA. One per invoice.
- "Request new link" in footer for expired or soon-to-expire tokens (OWN-04).
- Portal URL format: `portal.breeyo.app/v/{token}` -- short, WhatsApp-friendly, no query params.

**Portal responsive behavior:**

| Viewport | Layout | Max Content Width |
|----------|--------|------------------|
| 320-480px | Single column, full-width cards | 100% with 16px horizontal padding |
| 481-768px | Single column, centered cards | 480px centered |
| 769px+ | Single column, centered cards with larger margins | 480px centered |

The portal never becomes multi-column. It always renders as a single vertical flow regardless of screen width. This simplifies implementation and matches the mental model of a mobile-first experience.

(CONTEXT D-14 -- Claude's Discretion)

|-------------|----------------|----------------|

### Owner Portal Loading States

| Screen | Loading Pattern | Skeleton Shape | Rationale |
|--------|----------------|----------------|-----------|
| Magic link validation | Full-page centered spinner + "Verifying your link..." text | Breeyo logo + spinner + text | First thing owner sees; must feel intentional, not broken |
| Pet profile header | Skeleton: circle + 2 lines | Avatar placeholder + name/details lines | Loads first from token payload |
| Medical history section | Skeleton: 3 accordion rows | Rounded rect (12px radius) x 3 stacked | Matches final accordion layout |

| Payment processing | Inline spinner within "Pay Now" button + "Processing..." label | Button becomes disabled with spinner | Razorpay SDK overlay handles the rest |

Portal skeleton colors: same as mobile (`surfaceVariant` / `outlineVariant`).

**Portal loading sequence (progressive):**
1. HTML shell + sticky header render (< 500ms target)
2. Magic link token validated (API call, < 1s target)
3. Pet profile header populates (from validation response)
4. Medical history and invoices load in parallel (< 2s target)
5. Total FCP target: < 3 seconds on 4G (OWN-05)

## Copywriting Contract

Tone: Warm, direct, action-oriented. Never clinical or condescending. Use "you" not "the user." Short sentences. Hindi-translatable (avoid idioms, cultural metaphors).

### Global Patterns

| Element | Copy Pattern | Example |
|---------|-------------|---------|
| Primary CTA | `[Verb] [Noun]` | "Check In Patient", "Save Notes", "Add Item" |
| Secondary action | `[Verb]` or `[Verb] [Noun]` lowercase-friendly | "Cancel", "Skip for now", "View all" |
| Empty state heading | `No [items] yet` | "No patients in queue yet" |
| Empty state body | `[What to do next] to get started.` | "Tap + to check in your first patient." |
| Empty state illustration | Custom warm illustration (pet-themed) | Friendly dog sitting next to empty clipboard |
| Error state (field) | `[What went wrong]` | "Phone number must be 10 digits" |
| Error state (screen) | `[Problem]. [What to try].` | "Could not load queue. Pull down to try again." |
| Error state (network) | `[Status]. [What happens next].` | "You are offline. Changes will sync when you reconnect." |
| Success toast | `[What happened]` | "Patient checked in", "Notes saved", "Item added" |
| Destructive confirmation title | `[Action] [object]?` | "Remove patient from queue?" |
| Destructive confirmation body | `[Consequence]. [Reassurance if applicable].` | "This will mark them as no-show. You can re-add them later." |
| Destructive confirm button | `[Verb]` (red text, not filled) | "Remove" (text button, error color) |
| Destructive cancel button | `Cancel` (always) | "Cancel" (outlined or text, neutral) |

## Screen States Contract

Every screen MUST implement all 4 states (CONTEXT D-33).

### Mobile App Screen States

| State | Visual Pattern | Required Elements |
|-------|---------------|-------------------|
| **Empty** | Centered illustration + heading + body + CTA button | Custom illustration (warm/pet-themed), heading ("No [items] yet"), body text with next step, primary action button |
| **Loading** | Skeleton screen matching populated layout | Skeleton shapes match final content layout, shimmer animation at 1500ms loop, no text content visible |
| **Populated** | Full data display | All data fields rendered, interactive elements active, pull-to-refresh enabled |
| **Error** | Inline error banner OR full-screen error | Error message + retry action, offline indicator if network-related, fallback to cached data when available |

### Owner Portal Screen States

The portal has 6 distinct states (the standard 4 plus 2 link-specific states):

| State | Visual Pattern | Required Elements | Trigger |
|-------|---------------|-------------------|---------|
| **Validating** | Centered Breeyo logo + spinner + "Verifying your link..." | Logo (builds brand recognition), spinner, text | Initial page load before token is validated |
| **Loading** | Sticky header visible + skeleton sections for EMR and invoices | Header with clinic name, skeleton cards matching final layout | Token valid, data being fetched |
| **Populated** | Full pet profile + medical history accordion + invoice list | All data rendered, "Pay Now" buttons active, accordions interactive | Data loaded successfully |
| **Empty (no records)** | Pet profile header + "No medical records yet" + "No invoices yet" messages | Pet info visible (from token), warm empty state messages per section | Valid token but pet has no EMR/invoice data |
| **Expired Link** | Full-page: warning icon + "This link has expired" + "Request New Link" button | No pet data shown (token expired = no data access), clear CTA to get fresh link | Token expiry check fails (>7 days) |
| **Invalid Link** | Full-page: error icon + "This link is not valid" + "Please contact your clinic" | No pet data, no retry CTA (security: invalid tokens get no self-service recovery) | Token signature invalid, tampered, or not found |

## Accessibility Contract

WCAG 2.1 AA compliance (CONTEXT D-06, D-24).

| Requirement | Implementation |
|-------------|---------------|
| Color contrast (text) | 4.5:1 minimum for all text on backgrounds |
| Color contrast (UI) | 3:1 minimum for interactive element boundaries |
| Touch target | 44x44pt minimum (CONTEXT D-28), padding extends hit area |
| Focus indicators | 2px `primary` outline on all focusable elements |
| Screen reader | All components include `accessibilityLabel`, `accessibilityRole`, `accessibilityState` |
| Semantic structure | Headings use proper heading levels, lists use list roles |
| Color independence | Status never communicated by color alone -- always paired with icon/text/shape |
| Motion | `prefers-reduced-motion` disables all transitions |
| Text scaling | Supports system font scaling up to 1.5x without layout breakage |

### Owner Portal Accessibility

All mobile app accessibility requirements apply to the portal, plus:

| Requirement | Implementation |
|-------------|---------------|
| Semantic HTML | Portal uses `<header>`, `<main>`, `<section>`, `<article>`, `<footer>` -- no `<div>` soup |
| Heading hierarchy | `<h1>` = pet name, `<h2>` = section titles ("Medical History", "Invoices"), `<h3>` = visit dates |
| ARIA for accordions | `aria-expanded`, `aria-controls` on VisitAccordion toggle buttons |
| Payment button | `aria-label="Pay invoice [number] for [amount]"` on each "Pay Now" button |
| Link expiry screen | `role="alert"` on expired link message for screen reader announcement |
| Language | `lang="en"` or `lang="hi"` on `<html>` element, updated by language toggle |
| Focus management | After magic link validation, focus moves to pet profile heading |

## Token Export Format

Design tokens are exported as a TypeScript module consumed by React Native Paper's `PaperProvider` and available to all components via `useTheme()`.

```
packages/ui/src/theme/
  index.ts          -- Main theme export (MD3Theme object)
  colors.ts         -- Color palette constants
  typography.ts     -- Type scale definitions
  spacing.ts        -- Spacing scale constants
  elevation.ts      -- Elevation level definitions
  borderRadius.ts   -- Border radius constants
  animation.ts      -- Duration and easing constants
```

Token format: TypeScript `as const` objects with full type inference. No CSS variables (React Native does not use CSS). Web tokens (portal and Phase 9 dashboard) will be generated from the same source via a build script.

### Portal Token Output

```
packages/ui/src/theme/
  portal.css        -- CSS custom properties generated from colors.ts, spacing.ts, typography.ts
```

The `portal.css` file is auto-generated (not hand-maintained) and exports tokens as CSS custom properties:

```css
:root {
  --color-primary: #2E7D32;
  --color-on-primary: #FFFFFF;
  --color-background: #FFFBF5;
  --color-surface: #FFFBF5;
  /* ... all color tokens ... */

  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 16px;
  /* ... all spacing tokens ... */

  --font-family: 'Inter', system-ui, sans-serif;
  --font-size-body: 16px;
  --font-size-caption: 12px;
  --font-size-subheading: 16px;
  --font-size-heading2: 28px;
  /* ... portal-relevant typography tokens ... */

  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;
  /* ... all border radius tokens ... */
}
```

Build script: `packages/ui/scripts/generate-css-tokens.ts` reads the TypeScript token source files and outputs `portal.css`. This runs as a pre-build step for the web portal package.
