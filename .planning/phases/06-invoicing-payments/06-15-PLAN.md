<objective>
Deliver BIL-04 and the document half of BIL-07: three PDF templates and the missing print and download actions.

PDF generation is client-side via `expo-print`, reusing the Phase 4 pattern — four templates and a `useGeneratePdf` hook already ship in `apps/mobile/src/features/pdf/`. An older ROADMAP line proposed server-side `@react-pdf/renderer`; that is superseded, because it would add a React reconciler and font subsetting to the API for output the device already produces, and it would lose native print support.

Two Rule-46 requirements shape the invoice template. The document heading is not decoration: a registered clinic supplying only exempt services must issue a `BILL OF SUPPLY`, a mixed invoice to an unregistered pet owner is an `INVOICE-CUM-BILL OF SUPPLY` under CGST Rule 46A, and an unregistered clinic must print a plain `INVOICE` with no GSTIN and no tax line at all — printing `GST @ 18%` without registration is a Section 122 offence. The engine already computes `documentType`; the template must render it.

D-13's "system generates a payment receipt after webhook confirmation" is satisfied by the server creating the receipt record and the client rendering the PDF on demand when the user taps View Receipt. That keeps one PDF engine and avoids rendering documents nobody opens.

Purpose: BIL-04, plus the invoice-presentation half of BIL-07.
Output: three templates, five new hook functions, an extended share sheet, and two template test files.
</objective>
