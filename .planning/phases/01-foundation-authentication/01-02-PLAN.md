    **apps/api/src/modules/auth/token.service.ts:**
    Implement `TokenService` class exactly as in RESEARCH.md Pattern 2 with these specifics:
    - Constructor: accepts Fastify jwt instance and ioredis client
    - `generateTokenPair(userId: string, clinicId: string)`: Create familyId via nanoid(), tokenId via nanoid(). Sign access token with { sub: userId, clinicId, type: 'access' } expiring in 15 minutes. Sign refresh token with { sub: userId, clinicId, familyId, tokenId, type: 'refresh' } expiring in 30 days (per D-20). Store token family in Redis key `refresh:${familyId}` with 30-day TTL, value: JSON { userId, familyId, currentTokenId: tokenId, clinicId, createdAt: Date.now() }. Return { accessToken, refreshToken }.
    - `refreshTokens(refreshToken: string)`: Verify JWT. Get family from Redis `refresh:${familyId}`. If family not found, throw TOKEN_FAMILY_REVOKED. If currentTokenId !== decoded.tokenId, delete the family key (replay detection per RESEARCH.md) and throw TOKEN_REUSE_DETECTED. Otherwise, generate new token pair in the same family (delete old key, create new).
    - `revokeFamily(familyId: string)`: Delete `refresh:${familyId}` from Redis.
    - `revokeAllUserTokens(userId: string)`: Scan Redis keys matching `refresh:*`, parse each value, delete keys where parsed.userId === userId. Used for D-21 (password change forces logout on all devices).

    **apps/api/src/modules/auth/otp.service.ts:**
    Class `OtpService` with constructor accepting ioredis client:
    - `sendOtp(phone: string)`: Generate 6-digit OTP via crypto.randomInt(100000, 999999). Store in Redis key `otp:${phone}` with 300-second TTL (5 minutes). Track request count in `otp_count:${phone}` with 300-second TTL. If count > 3, throw OTP_RATE_LIMITED. Call SMS provider (MSG91 in production, mock in dev/test). Write OTP_SENT audit event. Return { message: 'OTP sent' }.
    - `verifyOtp(phone: string, otp: string)`: Get stored OTP from Redis `otp:${phone}`. If not found, throw OTP_EXPIRED. If doesn't match, throw OTP_INVALID. If matches, delete the key (one-time use). Return true.
    - SMS provider abstraction: Interface `SmsProvider { sendOtp(phone: string, otp: string): Promise<void> }`. Implement `MockSmsProvider` (logs to console) and `Msg91Provider` (calls MSG91 API). Select based on NODE_ENV.

    Add to **apps/api/src/modules/auth/auth.service.ts:**
    - `login(email: string, password: string, ipAddress: string, userAgent: string)`:
      1. Find user by email (case-insensitive). If not found, throw INVALID_CREDENTIALS.
      2. Check isActive. If false, throw ACCOUNT_DEACTIVATED.
      3. Check isEmailVerified. If false, throw EMAIL_NOT_VERIFIED.
      4. Verify password with argon2.verify(user.passwordHash, password). If fails, write LOGIN_FAILED audit event, throw INVALID_CREDENTIALS.
      5. Find user's first clinic (via clinic_members where isActive=true, order by createdAt). Use that as activeClinicId.
      6. Generate token pair via tokenService.generateTokenPair(user.id, clinicId).
      7. Write LOGIN_SUCCESS audit event.
      8. Return { accessToken, refreshToken, user: { id, email, fullName, clinics: [...] } }.

    - `otpLogin(phone: string, otp: string, ipAddress: string, userAgent: string)`:
      1. Verify OTP via otpService.verifyOtp(phone, otp).
      2. Find user by phone. If not found, throw INVALID_CREDENTIALS.
      3. Check isActive. If false, throw ACCOUNT_DEACTIVATED.
      4. If isPhoneVerified is false, set to true (per D-03: phone verified on first OTP login).
      5. Find user's first clinic. Generate tokens. Write OTP_VERIFIED + LOGIN_SUCCESS audit.
      6. Return same shape as login.

    - `refreshTokens(refreshToken: string)`:
      1. Call tokenService.refreshTokens(refreshToken). Returns new pair.
      2. Return { accessToken, refreshToken }.

    - `logout(userId: string, refreshToken: string, ipAddress: string, userAgent: string)`:
      1. Decode refresh token to get familyId (without full verification -- token may be expired).
      2. Call tokenService.revokeFamily(familyId).
      3. Write LOGOUT audit event.
      4. Return success.
