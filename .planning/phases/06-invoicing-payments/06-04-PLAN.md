<objective>
Define the shared contracts that the API and the mobile app both compile against: billing entity types, the invoice state machine, the GST constant set, and the Zod validation schemas.

The state machine goes in `@breeyo/types`, not in the API module, for the same reason `queue-status.ts` does: the mobile invoice-detail action bar must gate its Pay / Void / Refund / Credit Note buttons off the same transition table the server enforces, or the UI will offer actions that 409. The GST constants go in one file because GST slabs change by Council notification — GST 2.0 collapsed them to 5/18/40 on 22 Sept 2025 — so the slab list must be a one-line edit, and the *applied* rate must be frozen onto each finalized line rather than recomputed from the current constant.

Purpose: BIL-03 (mark paid/unpaid) and BIL-07 (full GST) are defined here as data contracts before any behaviour is written against them.
Output: extended `packages/types/src/billing.ts`, three constant modules, extended `packages/validators/src/billing.ts`, and unit tests for the state machine and the validators.
</objective>
