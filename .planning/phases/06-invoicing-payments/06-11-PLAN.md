<objective>
Implement D-12 refunds and D-22 credit notes — the two ways money comes back after an invoice is finalized and locked.

They are deliberately different mechanisms. A refund returns money that was actually collected and is bounded by `Σ captured payments`; a digital refund settles asynchronously over 2-5 business days, so the invoice carries a pending sub-state until `refund.processed` arrives and must never be marked refunded on the API call succeeding. A credit note is an accounting document that reduces the outstanding balance without touching the immutable original invoice — D-21 forbids editing a finalized invoice, so a partial correction is issued as a negative document referencing the original, with its own gap-free `CN-YYYYMM-XXXX` number.

Both must recompute tax with the same engine and the same frozen per-line rates as the original invoice: a credit note that recomputes from current settings would not reconcile with the invoice it credits.

Purpose: the refund and credit-note halves of BIL-03 and BIL-05, and the credit-note half of BIL-07.
Output: two services, two controllers, six routes, and two integration test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client refund request → money leaving the clinic | A refund moves real money out; the bound is the only thing preventing loss |
| finalized invoice → credit note | A credit note must reduce the balance without altering the immutable financial record |
| Razorpay refund API → refund state | A successful API call means a refund was requested, not settled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-66 | Tampering | refunding more than was ever paid | mitigate | `getRefundableAmount` computed inside a `FOR UPDATE` transaction as `Σ captured payments − Σ (pending + processed) refunds`; `REFUND_EXCEEDS_PAID` 400; sequential-partial-refund integration test |
