<objective>
Build the core stock operation APIs: FIFO dispensing with transactional row locking, stock adjustments with required reasons, stock-take with discrepancy calculation, par-level alerts with configurable expiry lead time, want-list generation with WhatsApp text format, stock movement history with CSV export, and return-to-stock flow. Also create the dispense/adjustment/stock-take/alert/want-list routes.

Purpose: These services implement the business-critical stock operations. FIFO dispensing is the most concurrency-sensitive operation in the entire inventory module -- it must be transactional with row locking to prevent over-dispensing. The alert and want-list services power the Attention card and reordering workflows.

Output: Fully tested dispense, adjustment, stock-take, alert, and want-list services with routes and controller wiring.

    Class `StockMovementService` with PrismaClient:

    - `recordMovement(tx: PrismaTransaction, data)`:
      Calculate runningTotal by reading the last StockMovement for this itemId+clinicId ordered by createdAt DESC. New runningTotal = (lastMovement?.runningTotal ?? 0) + data.quantity.
      Create StockMovement record. This is append-only -- no UPDATE or DELETE on movements (D-45).

    - `getHistory(clinicId, itemId, { page?, limit? })`:
      Find StockMovements where itemId and clinicId match, ordered by createdAt DESC. Paginate. Include user name. Return { movements, total }.

      Return all movements for item (within 12-month window per D-48) as flat objects suitable for CSV generation.

    **2. Create `apps/api/src/modules/inventory/fifo-dispense.service.ts`:**

    Class `FifoDispenseService` with PrismaClient, StockMovementService:

    Use the exact FIFO pattern from RESEARCH.md Pattern 2 (lines 327-400):

    - `dispense(clinicId, itemId, userId, userName, input: DispenseInput): Promise<DispenseResult>`:
      1. Validate with dispenseSchema
      2. Execute in prisma.$transaction():
         a. If overrideBatchId: SELECT FOR UPDATE the specific batch, verify it's not expired
         b. Else: SELECT FOR UPDATE all batches WHERE itemId AND clinicId AND currentQty > 0 AND isExpired = false AND (expiryDate IS NULL OR expiryDate > NOW()) ORDER BY receivedAt ASC
         c. Check totalAvailable = sum(currentQty). If < input.quantity, throw InsufficientStockError(itemId, input.quantity, totalAvailable)
         d. Deduct FIFO: loop batches, deduct min(remaining, batch.currentQty) from each
         e. For each batch deducted: update StockBatch.currentQty decrement, create StockMovement via stockMovementService.recordMovement with type='dispensed', quantity=-deductAmount, batchId, consultationId, invoiceId
         f. Update InventoryItem.currentStock decrement by total quantity
      3. Return { deductions, newTotal, movementIds }

    - `returnToStock(clinicId, movementId, userId, userName)`:
      1. Find the original dispensed movement
      2. Verify type='dispensed' and quantity is negative
      3. In transaction:
         a. Restore batch.currentQty by |movement.quantity|
         b. Create new StockMovement with type='returned', quantity=|original.quantity| (positive)
         c. Increment InventoryItem.currentStock
      4. Return the return movement

    **3. Create `apps/api/src/modules/inventory/stock-adjustment.service.ts`:**

    Class `StockAdjustmentService` with PrismaClient, StockMovementService:

    - `adjust(clinicId, itemId, userId, userName, input: StockAdjustmentInput)`:
      1. Validate with stockAdjustmentSchema -- reason is REQUIRED (D-04)
      2. Calculate quantity: if type='add' -> +input.quantity, if type='remove' -> -input.quantity

         b. Update InventoryItem.currentStock by signed quantity
      5. Return movement

    **4. Create `apps/api/src/modules/inventory/stock-take.service.ts`:**

    Class `StockTakeService` with PrismaClient, StockMovementService:

    - `processStockTake(clinicId, userId, userName, input: StockTakeInput): Promise<StockTakeSummary>`:
      1. Validate with stockTakeSchema
      2. For each entry in input.entries:
         a. Get current item (read currentStock and sellingPrice)
         b. Calculate difference = entry.actualCount - item.currentStock
         c. If difference !== 0: create StockMovement with type='stock_take', reason='stock_take', quantity=difference
         d. Update InventoryItem.currentStock = entry.actualCount (absolute set in transaction)
         e. Record result: { itemId, itemName, systemQty, actualQty, difference, valueDifference: difference * sellingPrice }
      3. All within a single transaction (re-read currentStock inside TX to handle concurrency per RESEARCH.md Pitfall 5)
      4. Calculate summary: itemsCounted, matches (difference===0), discrepancies, overCount, underCount, totalValueDifference
      5. Return StockTakeSummary

    **1. Create `apps/api/src/modules/inventory/par-level-alert.service.ts`:**

    Class `ParLevelAlertService` with PrismaClient:

    - `getLowStockItems(clinicId): Promise<LowStockItem[]>`:
      Use raw SQL from RESEARCH.md Pattern 6 (lines 610-622):
      ```sql
      SELECT i.id, i.name, i.category, i.unit, i."selling_price" as "sellingPrice", i."par_level" as "parLevel",
        COALESCE(SUM(b."current_qty"), 0) as "currentStock"
      FROM "inventory_items" i
      LEFT JOIN "stock_batches" b ON b."item_id" = i.id AND b."is_expired" = false
      WHERE i."clinic_id" = $clinicId AND i."par_level" IS NOT NULL AND i."is_active" = true
      GROUP BY i.id
      HAVING COALESCE(SUM(b."current_qty"), 0) < i."par_level"
      ORDER BY (COALESCE(SUM(b."current_qty"), 0)::float / i."par_level") ASC
      ```

    - `getExpiringSoonItems(clinicId, leadDays: number = 30): Promise<ExpiringBatchItem[]>`:
      Use pattern from RESEARCH.md (lines 625-637):
      Query StockBatch where currentQty > 0 AND isExpired = false AND expiryDate <= now() + leadDays AND expiryDate > now(). Include item name and unit. Order by expiryDate ASC. (D-21 configurable lead time).

    - `getExpiredItems(clinicId): Promise<ExpiringBatchItem[]>`:
      Query StockBatch where currentQty > 0 AND (expiryDate <= now() OR isExpired = true). Include item name and unit. Order by expiryDate ASC.

    - `getAlertCounts(clinicId, leadDays: number = 30): Promise<{ lowStockCount, expiringCount, expiredCount }>`:
      Run all three queries and return counts. Used for Attention card tab counts (D-26).
