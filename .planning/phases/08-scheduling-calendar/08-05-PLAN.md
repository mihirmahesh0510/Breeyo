<objective>
Build the availability half of the scheduling module: the pure slot-generation engine, the three-table availability repository, and the service that resolves a vet's real hours for a given date and validates blocked periods. Also extend the shared `AuditEvent` enum with the scheduling events every later plan needs.

Purpose: D-01, D-04, D-05 and D-06 together define "when can this vet actually be booked", and D-02 makes the answer duration-dependent. RESEARCH Pattern 1 chose three small typed tables over a JSON blob precisely so this resolution is a three-query lookup. `08-PATTERNS.md` § No Analog Found flags `slot.service.ts` as genuinely greenfield with no transplant source (Phase 7's version does not exist), so it is written as exported plain functions with zero database access — that is what makes it exhaustively unit-testable without fixtures.
Output: `slot.service.ts`, `availability.repository.ts`, `availability.service.ts`, `scheduling.types.ts`, the `AuditEvent` extension, and unit tests for the pure engine and the service's validation rules.
</objective>
