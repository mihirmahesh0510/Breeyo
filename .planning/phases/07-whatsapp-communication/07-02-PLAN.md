<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff client → API request body | Untrusted JSON crosses here; these schemas are the parse-don't-validate boundary |
| owner WhatsApp reply → inbound payload router | Owner-controlled strings arrive as button/list payload ids |
| template variable → owner-visible message body | Staff-supplied variable text becomes message content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Tampering | template variable injection (owner_name carrying content that alters template meaning) | mitigate | Every template variable is `z.string().max(n)` with per-field caps; template structure is fixed in the registry so variable content cannot add components |
| T-07-02-02 | Elevation of Privilege | owner reply crafted as `booking:cancel:<uuid>` to cancel a booking | mitigate | `WA_BUTTON_PAYLOAD_PATTERN` allowlists only book:start, booking:confirm:<uuid>, booking:slot:<uuid>, STOP and BOOK — cancel/move are not expressible as inbound payloads (D-09) |
| T-07-02-03 | Spoofing | unvalidated webhook envelope routed as a real event | mitigate | `webhookPayloadSchema` shapes the Meta envelope; the webhook handler (07-09) parses through it after HMAC verification and before routing |
| T-07-02-04 | Information Disclosure | Meta-specific fields leaking into shared client-visible types | mitigate | Shared types use domain vocabulary only; acceptance criteria asserts no `messaging_product` string in `packages/types/src/whatsapp.ts` (Anti-Pattern A1) |
| T-07-02-05 | Denial of Service | unbounded inbox page size or search string | mitigate | `inboxQuerySchema` caps limit at 50 and search at 100 characters |
| T-07-02-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages (07-RESEARCH § Package Legitimacy Audit). Any install would require slopcheck `-e npm` plus a blocking human checkpoint |
</threat_model>
