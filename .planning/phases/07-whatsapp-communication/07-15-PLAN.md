<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device user role → visible screens | The role gate decides what a signed-in staff member is shown |
| server message content → rendered text | Owner-authored replies are displayed to staff |
| tel: deep link → dialer | A phone number from server data is handed to the OS |
| navigation route → screen | A direct route entry must not bypass the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-15-01 | Elevation of Privilege | a non-Front-Desk/Admin user reaching the inbox by typing the route | mitigate | `WhatsAppAccessGate` wraps both route files, not just the nav entry, so a direct route entry is refused. The gate is usability-level; the API independently enforces `SEND_WHATSAPP` and `MANAGE_CLINIC_SETTINGS`, so bypassing the client gate grants nothing (D-20) |
| T-07-15-02 | Elevation of Privilege | staff sending arbitrary free text to an owner | mitigate | No free-text composer exists; the only send path is `TemplateSendSheet` with a server-rendered body. Acceptance criteria greps for zero composer identifiers (UI-SPEC: no free-text NLP in Beta) |
| T-07-15-03 | Tampering | owner-authored reply text rendered as markup or interpreted as a command | accept | React Native `Text` renders strings literally with no markup interpretation, and inbound routing happens server-side against an allowlist; the screen only displays |
| T-07-15-04 | Information Disclosure | a thread from another clinic displayed after a clinic switch | mitigate | Every query key is namespaced by `activeClinicId` and the API scopes by the JWT, so switching clinics cannot surface cached cross-tenant threads |
| T-07-15-05 | Information Disclosure | owner phone numbers written to logs or crash reports from the screens | mitigate | No console logging of thread or message data is added; the `tel:` link is constructed inline and not logged |
| T-07-15-06 | Repudiation | a failed message disappearing on retry, hiding what happened | mitigate | Retry creates a new server row and the screen keeps the failed bubble and its reason visible; human verification step 10 checks exactly this |
| T-07-15-07 | Denial of Service | unbounded thread list growth on scroll | mitigate | Cursor pagination with the server capping page size at 50; `onEndReached` fetches one page at a time |
| T-07-15-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; the mobile dependency set was resolved and gated in 07-03 |
</threat_model>
