<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff client → privileged action endpoints | Cancel, move, opt-out, consent and config changes are all state-changing |
| inbound webhook → booking transitions | An owner must not reach staff-only transitions |
| Admin config → real message sending | The provider setting decides whether real owners get messaged |
| consent ledger → compliance record | Records must be append-only and attributable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-13-01 | Elevation of Privilege | an owner's WhatsApp reply cancelling or moving a booking | mitigate | `cancelBooking`/`moveBooking` require `actorUserId` sourced from `request.user.id`; the payload grammar and inbound router exclude `booking:cancel:*` and `booking:move:*`; booking-authz integration cases POST those payloads to the webhook and assert no state change (D-09) |
| T-07-13-02 | Elevation of Privilege | non-Admin switching the provider to cloud-api and messaging real pet owners | mitigate | Config read and write require `requirePermission('MANAGE_CLINIC_SETTINGS')` (Admin-only); integration cases assert 403 for FrontDesk on both GET and PATCH (D-20) |
| T-07-13-03 | Elevation of Privilege | one clinic writing another clinic's simulator configuration | mitigate | The config routes take no clinic id — clinicId comes from the JWT; acceptance criteria asserts no clinicId appears in the schema file |
| T-07-13-04 | Information Disclosure | cross-tenant booking or owner access via a guessed uuid | mitigate | Every handler scopes by `request.user.activeClinicId` and cross-tenant ids return 404 rather than 403 |
| T-07-13-05 | Repudiation | a booking cancelled or an owner opted out with no record of who did it | mitigate | WHATSAPP_BOOKING_CANCELLED / WHATSAPP_BOOKING_MOVED / WHATSAPP_OPT_OUT / WHATSAPP_NUMBER_MARKED_INVALID / WHATSAPP_CONSENT_GRANTED / WHATSAPP_CONSENT_WITHDRAWN audit entries all carry the actor; `acknowledgedAt` records who cleared a Needs action flag (D-04) |
