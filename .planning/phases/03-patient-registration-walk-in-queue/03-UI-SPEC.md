# Phase 3 -- UI Design Contract

> Visual and interaction contract for Patient Registration and Walk-in Queue. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase is the first feature phase, consuming the design system established in Phase 2. All tokens, base components, and interaction patterns from 02-UI-SPEC.md are inherited and NOT re-declared here. This document specifies only what Phase 3 adds or refines for registration, check-in, queue board, patient search, and pet profile screens.

## Spacing Scale

Inherited from Phase 2 UI-SPEC (8px base unit). No modifications.

| Token | Value | Phase 3 Usage |
|-------|-------|---------------|
| `spacing.xs` | 4px | Icon-to-label gap in queue cards, badge internal padding |
| `spacing.sm` | 8px | Chip padding in visit reason picker, form field compact gaps in quick registration |
| `spacing.md` | 16px | Queue card internal padding, form field gaps in wizard, bottom sheet content padding |
| `spacing.lg` | 24px | Section gaps between In Consult / Waiting / Done groups, wizard step spacing |
| `spacing.xl` | 32px | Screen-level horizontal margins, gap between queue sections |
| `spacing.2xl` | 40px | Vertical gap above "Call Next" button region |
| `spacing.3xl` | 48px | Bottom padding above tab bar safe zone |

Exceptions:
- **Touch targets**: 44x44pt minimum enforced on all queue card tap zones, status badges, FAB, and bottom sheet action buttons (Phase 2 standard).
- **Queue card height**: 80px minimum (spacious density per Phase 2 Information Density rules).
- **Emergency card left border**: 4px wide `error` (#BA1A1A) left border to indicate emergency status. Uses `spacing.xs` width.
- **Check-in bottom sheet mobile input**: Input field height 48px (padded 44pt tap target + 4px visual breathing room).

## Interaction Contracts

### 2-Tap Check-In Flow (QUE-01)

```
User taps FAB "Check In"
  |
  v
BottomSheet opens (CheckInSheet)
  -> Focus on mobile number input (numeric keyboard auto-opens)
  -> User types 10-digit mobile number
  -> Auto-lookup after 10 digits entered (no submit button needed)
  |
  +-- Owner found:
  |     -> Show owner name + mobile
  |     -> Show list of pets as tappable cards
  |     -> User taps pet card = TAP 2
  |     -> Optional: VisitReasonPicker bottom sheet appears
  |     -> User taps reason or "Skip"
  |     -> Check-in complete: toast, return to queue
  |
  +-- Owner not found:
        -> Show "New patient" message
        -> Show "Register New Patient" button
        -> Tapping navigates to RegisterPatientScreen
        -> After registration: auto-check-in option
```

**Tap count:** FAB (tap 1) + pet card (tap 2) = 2 taps for returning patients. Visit reason is optional and does not count.

### Quick Inline Registration (D-12)

```
From CheckInSheet "Register New Patient" button:
  -> Navigate to RegisterPatientScreen
  -> Mobile pre-filled from check-in input
  -> Minimal fields: owner name, pet name, species
  -> On "Register": create owner + pet, auto-create queue entry
  -> Return to queue with toast
```

### Queue Status Transitions (D-18)

```
Tap status badge on queue card:
  WAITING -> IN_CONSULT (assigns current user as treating vet)
  IN_CONSULT -> DONE (marks completed)
  Other transitions: not available via tap (greyed badge)

Long-press status badge:
  WAITING -> NO_SHOW (confirmation bottom sheet)
  IN_CONSULT -> NO_SHOW (confirmation bottom sheet)
  DONE -> no action (terminal)
  NO_SHOW -> no action (terminal)

Swipe gestures on queue card:
  Swipe right -> DONE (green reveal, check icon)
  Swipe left -> NO_SHOW (red reveal, X icon, then confirmation)
```

### Call Next (D-17)

```
User taps "Call Next" button at top of queue:
  -> API selects: emergency patients first (FIFO), then regular FIFO
  -> Selected patient moves from WAITING to IN_CONSULT
  -> Current user assigned as treating vet
  -> All devices update via Socket.IO
  -> Haptic feedback (medium impact)

Alternative: Tap any specific WAITING patient card
  -> Same as Call Next but for the specific patient
  -> Useful for calling emergency patients or specific requests
```

### Patient Search (D-25)

```
User types in search bar on Patients tab:
  -> After 1 character: show "Type at least 2 characters to search"
  -> After 2+ characters: 300ms debounce, then API call
  -> Results grouped by owner: owner name + mobile, then their pets listed below
  -> Matching text highlighted with primary color underline
  -> Tap pet row -> navigate to PetProfileScreen
  -> Tap owner row -> navigate to OwnerDetailScreen
  -> Clear search -> return to recent patients list
```

### Real-Time Queue Updates (D-33, D-34)

```
Socket.IO connected:
  -> Queue updates appear within 1-2 seconds
  -> New check-in: card animates in at bottom of Waiting section
  -> Status change: card animates to new section position
  -> Haptic feedback on remote changes (if user enabled)

Socket.IO disconnected:
  -> Yellow "Offline" banner appears at top (200ms slide-down)
  -> Queue shows last-known state
  -> All modification actions disabled (FAB greyed, status badges non-interactive)
  -> "You are offline. Queue may be outdated." text

Socket.IO reconnected:
  -> Banner slides up (200ms)
  -> Full queue data re-fetched
  -> All actions re-enabled
```

## Animation & Motion (Phase 3 Specific)

All timings from Phase 2 UI-SPEC animation table. Phase 3 applies them as follows:

| Animation | Duration | Easing | Trigger |
|-----------|----------|--------|---------|
| Queue card enter | 200ms | `Easing.bezier(0.4, 0, 0.2, 1)` | New patient checked in (local or remote) |
| Queue card status change | 300ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Badge color transition + card moves to new section |
| Queue card section reorder | 250ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Card slides to new position within section after reorder |
| Queue card exit (done/no-show) | 200ms | `Easing.out(Easing.ease)` | Card fades + slides down into Done section |
| Check-in bottom sheet open | 200ms | `Easing.bezier(0.4, 0, 0.2, 1)` | FAB tap |
| Check-in bottom sheet dismiss | 150ms | `Easing.out(Easing.ease)` | Swipe down or backdrop tap |
| Patient lookup loading | Skeleton shimmer 1500ms loop | `linear` | After 10 digits entered, during API call |
| Toast enter | 150ms slide-up | `Easing.out(Easing.ease)` | Check-in success, status change |
| Toast exit | 100ms fade-out | `Easing.out(Easing.ease)` | Auto-dismiss after 3000ms |
| Offline banner enter | 200ms slide-down | `Easing.out(Easing.ease)` | Socket.IO disconnect |
| Offline banner exit | 200ms slide-up | `Easing.out(Easing.ease)` | Socket.IO reconnect |
| Search results appear | 150ms fade-in | `Easing.out(Easing.ease)` | After debounce + API response |
| Wizard step transition | 250ms slide | `Easing.bezier(0.4, 0, 0.2, 1)` | Next/Back in registration wizard |
| Edit mode toggle | 200ms | `Easing.bezier(0.4, 0, 0.2, 1)` | Save/Cancel buttons fade in/out |
| Swipe reveal (queue card) | Spring animation | `Easing.bezier(0.4, 0, 0.2, 1)` | Swipe right/left reveals action background |

All animations use `useNativeDriver: true` where possible. `prefers-reduced-motion` snaps all transitions to final state instantly (Phase 2 rule).

| Event | Haptic Type | Audio | Configurable |
|-------|------------|-------|-------------|
| Check-in confirmed (own device) | `Haptics.notificationAsync(Success)` | None | No (always on) |

| Call Next confirmed | `Haptics.notificationAsync(Success)` | None | No |
| Error / validation failure | `Haptics.notificationAsync(Error)` | None | No |
| Destructive action confirmed | `Haptics.notificationAsync(Warning)` | None | No |

| Scenario | Display | Format |

| Sufficient data (5+ completed consults in last 7 days) | Computed: position x rolling average | "~[N] min" |
| Wait less than 5 minutes | Show as minutes | "~5 min" |
| Wait 5-60 minutes | Show as minutes | "~[N] min" |
| Wait over 60 minutes | Show as hours + minutes | "~1 hr 15 min" |
| Position 0 (next in line) | Special text | "Next" |
| In Consult | No wait display | Duration shown: "[N] min in consult" |
| Update frequency | Recalculated on every queue change | Pushed via Socket.IO |
