# Phase 05 Plan 06 (Task 1): Stock Receipt Screen and Stock Adjustment Sheet Summary

Built the stock receipt screen (D-01, D-03, D-09, D-11, D-27) and stock adjustment bottom sheet (D-04) -- the two of Plan 06's three stock-operation flows covered by Task 1. Task 2 (dispense screen with FIFO batch display) is not part of this task and is covered separately.

## What Was Built

- **`components/StockReceiptForm.tsx`** -- form fields per UI-SPEC "Stock Receipt Form": item name read-only header, Quantity Received (required), Lot/Batch Number (optional), Expiry Date (required note shown when the item's category is in `EXPIRY_REQUIRED_CATEGORIES`, D-27), Purchase Price per unit (optional), Distributor (optional). Uses `@breeyo/ui`'s `FormField` for every field, with placeholder-style guidance surfaced via `helperText` (the component has no separate `placeholder` prop -- see Deviations). Re-exports `isExpiryRequiredForCategory`/`EXPIRY_REQUIRED_NOTE`/the form data types from the new logic module for backward-compatible imports.
- **`screens/StockReceiptScreen.tsx`** -- composes `StockReceiptForm`, resolves `itemName`/`unit`/`category` from `useInventoryItem` (falling back to route params while that fetch is in flight -- see Deviations on why route params alone aren't relied on), validates + submits via the new `useReceiveStock` mutation, and gives `Haptics.notificationAsync` (Success/Error) + `showToast` feedback exactly per the UI-SPEC copy ("Receive Stock" title/button, "[N] [unit] of [Item Name] received" success toast).
- **`screens/StockAdjustmentSheet.tsx`** -- bottom sheet built on `@breeyo/ui`'s `BottomSheet` (see Deviations for why, not `@gorhom/bottom-sheet`), showing "Current stock: [N] [unit]", an Add/Remove `SegmentedButtons` toggle, a `Quantity` field, a required `Reason` chip row rendered from `ADJUSTMENT_REASONS` (D-04), an optional `Notes` field, and "Apply Adjustment"/"Cancel" buttons. Submits via the new `useAdjustStock` mutation with the same haptic+toast pattern, using the UI-SPEC's distinct add/remove success copy.
- **`lib/stock-receipt-logic.ts`** / **`lib/stock-adjustment-logic.ts`** (new, not in the plan's literal file list -- see Deviations) -- pure validation/submission functions with zero React/React Native imports: `isExpiryRequiredForCategory`, `buildStockReceiptSubmission` (D-27 category-conditional expiry requirement, then `stockReceiptSchema`), `computeSignedAdjustmentQuantity`, `getAdjustmentSuccessToast`, `buildStockAdjustmentSubmission` (D-04 required-reason check, then `stockAdjustmentSchema`).
- **`hooks/useInventoryApi.ts`** (additive only) -- added `useReceiveStock(clinicId, itemId)` (`POST /inventory/items/:itemId/receive`, invalidates item/summary/movements) and `useAdjustStock(clinicId, itemId)` (`POST /inventory/items/:itemId/adjust`, invalidates item/summary/movements/alerts -- an adjustment can cross a par-level threshold). No existing export in this file was changed; only the `@breeyo/validators` type import was extended and two new hooks appended at the end of the file.

# Phase 05 Plan 06 (Task 2): Dispense Screen with FIFO Batch Display Summary

Built the dispense screen (D-22 FIFO auto-select + manual override, D-25 expired-batch blocking) plus every supporting component: the quantity stepper, FIFO batch display, batch override list, expired-batch error banner, and the D-60 owner-attribution picker for counter sales. This is the third and final stock-operation flow from Plan 06 -- Task 1 (stock receipt, stock adjustment) is documented above and was left untouched.

## What Was Built

- **`lib/fifo-dispense-logic.ts`** (new, following Task 1's `lib/` pure-logic-extraction convention) -- zero React/React Native imports: `isBatchExpired` (D-25, server flag OR a past `expiryDate`), `sortBatchesByReceivedAt`/`selectFifoBatch` (D-22 FIFO ordering + auto-selecting the oldest non-expired batch with stock, `null` when none qualify), `clampQuantity` (min/max clamping with a sane fallback when `max < min`, i.e. zero stock), `formatExpiryDate` (DD MMM YYYY, matching `BatchList.tsx`'s existing convention), `getInsufficientStockError`/`getExpiredBatchError` (exact UI-SPEC copy), and `buildDispenseSubmission` (D-25 expired-batch block -> insufficient-stock check -> `dispenseSchema`, only attaching `overrideBatchId` when the batch in use differs from the FIFO pick, per D-22).
- **`tests/inventory/fifo-dispense-logic.test.ts`** -- 35 tests written and passing against the pure module above, covering all three logic areas the task called out for TDD (FIFO auto-selection display logic, expired-batch detection, quantity clamping) plus the submission-building pipeline (override-vs-FIFO payload shape, D-25 blocking, D-49 `consultationId`/D-60 `ownerId` passthrough, schema-level rejection of non-positive quantities).
- **`components/QuantityStepper.tsx`** -- 48x48 `-`/`+` `Pressable`s either side of a numeric `TextInput`, unit label alongside. Each button does a 100ms `Animated.timing` scale-to-0.97-and-back on press plus `Haptics.impactAsync(Light)`; both buttons and the typed-in value are clamped via `clampQuantity`. `atMin`/`atMax` (derived from `value`/`min`/`max`) disable the respective button.
- **`components/FifoBatchDisplay.tsx`** -- caption ("Oldest batch selected (FIFO)" or "Override active" when `isOverridden`), "From batch: [lotNumber], Exp: [DD MMM YYYY]" line, "[currentQty] [unit] available" line, and a "Use different batch" text button that toggles `BatchOverrideList` visibility in the parent screen.
- **`components/BatchOverrideList.tsx`** -- all batches sorted oldest-first via `sortBatchesByReceivedAt` (same order FIFO uses), each row showing lot number/qty/expiry/received date; expired rows (D-25) are `disabled` `Pressable`s with an "EXPIRED" badge and reduced opacity so they read as inert rather than tappable; the currently-active batch is highlighted.
- **`components/ExpiredBatchBlocker.tsx`** -- error banner (`errorContainer` background) rendered by `DispenseScreen` whenever the batch actually in use turns out expired (e.g. every batch is expired so `selectFifoBatch` returns `null` and the caller still has a stale/override batch reference). Reuses `getExpiredBatchError` so its text is guaranteed to match `buildDispenseSubmission`'s rejection message.
- **`hooks/useOwnerSearch.ts`** (new, not in the plan's literal file list -- see Deviations) -- debounced (300ms, 2-char minimum) owner search, deduping `/api/v1/patients/search`'s per-pet rows down to one row per owner.
- **`components/OwnerAttributionPicker.tsx`** (D-60) -- three states: collapsed ("Attach to owner (optional)" text button), expanded (search input + result rows via `useOwnerSearch`, "Cancel"), selected (`BreeyoChip` with the owner's name + a `BreeyoIconButton` "close" icon to clear). The helper caption "Links this sale to the owner's account for invoicing" is shown in all three states.
- **`hooks/useFifoDispense.ts`** -- `POST /inventory/items/:itemId/dispense`, accepting the full `DispenseSchemaInput` shape (`quantity`, `overrideBatchId?`, `consultationId?`, `invoiceId?`, `ownerId?`). Invalidates `['inventory','item',...]`, `['inventory','summary',...]`, `['inventory','alerts',...]`, and `['inventory','movements',...]` on success -- same invalidation shape as `useReceiveStock`/`useAdjustStock` plus `alerts` (a dispense is the operation most likely to cross a par-level threshold).
- **`screens/DispenseScreen.tsx`** -- composes all of the above: "Dispense [Item Name]" title, "Available: [N] [unit]" line, a "Counter Sale" badge (when there's no `consultationId`, D-52) or a "Linked to consultation: [Pet Name]" caption (when there is one, D-49), the `QuantityStepper` (min 1, max = `item.currentStock`), `FifoBatchDisplay` with the override toggle revealing `BatchOverrideList`, `ExpiredBatchBlocker` when the active batch is expired, `OwnerAttributionPicker` + a live "For: [Owner Name]" / "No owner attached" caption rendered only when there's no `consultationId` (D-60/D-52), and "Dispense"/"Cancel" buttons. Submission runs through `buildDispenseSubmission` before calling `useFifoDispense`, with the same `Haptics.notificationAsync` + `showToast` success/error pattern as `StockReceiptScreen`/`StockAdjustmentSheet`.
