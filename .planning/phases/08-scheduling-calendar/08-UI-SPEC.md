### shadcn Gate — resolved as "not applicable"

The gate was evaluated and resolved **without a user question** because upstream artifacts already answer it:

1. **A design system already exists.** `@breeyo/ui` ships 26 components and 6 token modules; Phase 02 existed specifically to establish it. shadcn would be a second, competing system.
2. **D-25 is a locked decision** that names the web approach exactly: *"built with plain React + the existing design-token CSS (`packages/ui/src/theme/portal.css`)"*. Initializing shadcn would contradict a locked decision.
3. **The primary surface is React Native**, where shadcn (a React-DOM/Tailwind/Radix system) cannot run at all.

`components.json` is absent and must stay absent. Registry safety gate: **not applicable** (see § Registry Safety).

### ⚠️ Blocking prerequisite (discovered this session — planner must schedule this)

`apps/mobile/package.json` declares **neither `@breeyo/ui` nor `react-native-paper`**, yet existing Phase 3/4 mobile code imports both:

- `apps/mobile/src/features/queue/screens/QueueScreen.tsx:3` → `import { Text, FAB, ActivityIndicator } from 'react-native-paper'`
- `apps/mobile/src/features/queue/screens/QueueScreen.tsx:6` → `import { showToast } from '@breeyo/ui'`
- `apps/mobile/src/features/queue/components/QueueBoard.tsx:3` → `import { EmptyState } from '@breeyo/ui'`
- `apps/mobile/src/features/queue/components/QueueCardItem.tsx:5` → `import { StatusBadge } from '@breeyo/ui'`

Verified unresolvable: `apps/mobile/node_modules/@breeyo/` contains only `shared`, `types`, `validators` — no `ui`. `react-native-paper` exists only in `packages/ui/node_modules/`, not in `apps/mobile/node_modules/` or the root. This is consistent with the STATE.md note *"react-native-paper not in mobile dependencies"* and means the Phase 3/4 queue screens cannot currently bundle.

**Every mobile deliverable in this contract depends on the fix.** Add to `apps/mobile/package.json` before `08-05-PLAN.md` work begins:

```bash
pnpm --filter @breeyo/mobile add @breeyo/ui@workspace:* react-native-paper@^5.15.1 react-native-safe-area-context@^5.7.0
```

If the planner instead chooses to keep mobile on plain React Native primitives, this contract's mobile component inventory must be re-specified — flag back rather than silently substituting.

Web prerequisite (already identified in `08-RESEARCH.md` § Environment Availability):

```bash
pnpm --filter @breeyo/web add socket.io-client@^4.8.3
```

Plus `apps/web/app/layout.tsx` must `import '@breeyo/ui/src/theme/portal.css'` and `apps/web/package.json` must add `@breeyo/ui: workspace:*` — otherwise no web token in this contract resolves.

## Spacing Scale

Phase 8 uses this subset of `packages/ui/src/theme/spacing.ts` (all multiples of 4):

| Token | Value | Usage in Phase 8 |
|-------|-------|------------------|
| xs | 4px | Icon-to-label gaps, vet rail width, badge row gaps |
| sm | 8px | Compact stacking inside appointment cards, chip gaps, filter bar item gaps |
| md | 16px | Default: screen horizontal padding, card padding, agenda row padding, grid cell padding |
| lg | 24px | Section separation (date header ↔ agenda list, form field groups in booking sheet) |
| xl | 32px | Empty-state internal padding, web page gutter |
| 3xl | 48px | Empty-state top offset; web week-grid header height |
| 5xl | 64px | Web week-grid **30-minute row height** (see § Web Week Grid) |

**Not used in Phase 8:** `xxs` (2px — not a multiple of 4), `2xl` (40px), `4xl` (56px, except the one exception below).

### Exceptions

| Exception | Value | Justification |
|-----------|-------|---------------|
| Minimum interactive target | **44 × 44px** | One-handed mobile constraint (PROJECT.md). Matches existing `QueueCardItem` avatar (44px) and RN Paper FAB `customSize={56}`. Applies to date arrows, vet filter chips, appointment rows, and every web grid cell that accepts a click-to-book. |
| Web time-gutter width | **56px** (`4xl`) | Fixed left column holding `9:00 AM`-style caption labels; 56px is the narrowest width that fits `12:30 PM` at 12px caption without wrapping. |
| Inherited `StatusBadge` padding | `paddingVertical: 2px` | Pre-existing internal of `packages/ui/src/atoms/StatusBadge/StatusBadge.ts:92`. Phase 8 reuses the component as-is and does **not** introduce 2px spacing in any new code. |

## Typography

Exactly **3 sizes**, exactly **2 weights**. All values are existing `packages/ui/src/theme/typography.ts` tokens — Phase 8 adds no new type token.

| Role | Token | Size | Weight | Line Height | Ratio | Used for |
|------|-------|------|--------|-------------|-------|----------|
| Heading | `heading2` | 28px | 400 (regular) | 36px | 1.29 | Screen title only — "Schedule" (mobile), "Schedule" (web `<h1>`) |
| Body / Label | `subheading` | 16px | **500 (medium)** | 24px | 1.50 | Pet name on appointment card, day-column headers, vet name in filter, button labels, form field labels |
| Body | `body` | 16px | 400 (regular) | 24px | 1.50 | Owner name, service name, sheet/dialog body copy, empty-state description |
| Caption | `caption` | 12px | 400 (regular) | 16px | 1.33 | Time labels, time-gutter axis, "in 20 min", status badge text, vet initials, helper text |

**Weights:** `400` regular and `500` medium. **No other weight is permitted** — do not use 600/700 anywhere in this phase (the token file defines only 400 and 500).

**Forbidden in Phase 8:** `display` (45px), `heading1` (32px), `overline` (11px). `overline` is excluded specifically because 11px sits 1px from `caption` (12px) and would create an indistinguishable fourth size — web week-grid time-axis labels use `caption` 12px instead.

**Mobile ↔ Paper mapping** (mobile code uses RN Paper `variant` props, so bind them to these tokens):

| This contract | RN Paper `variant` |
|---------------|--------------------|
| Heading 28/400 | `headlineSmall` |
| Body-Label 16/500 | `titleMedium` |
| Body 16/400 | `bodyLarge` |
| Caption 12/400 | `bodySmall` / `labelSmall` |

### Accent (`#2E7D32` primary green) reserved for — exhaustive list

1. The **one** primary CTA per surface: mobile "Book Appointment" FAB; web "New Appointment" button.
2. The confirm button inside the booking sheet/drawer ("Confirm Booking").
3. The **"now" time indicator line** on the web week grid and the mobile day agenda (2px rule + 8px dot).
4. Today's date number in the mobile date navigator, and today's column header underline (2px) on the web grid.
5. Selected state of a slot the user is actively booking into (2px `primary` border on the slot, fill stays `#FFFBF5`).
6. `CHECKED_IN` appointment badge (`primaryContainer` #C8E6C9 fill / `onPrimaryContainer` #1B5E20 text — the container pair, not solid primary).

**Not accent:** secondary buttons (outlined, `outline` border + `onSurface` text), links, plain icons, card borders, filter chips in unselected state, section headers, or any hover state. Explicitly **never** "all interactive elements."

### Destructive (`#BA1A1A` error) reserved for — exhaustive list

1. Confirm button in the "Cancel appointment?" dialog.
2. Confirm button in the "Mark as No-show?" dialog (reuses Phase 3 pattern).
3. `NO_SHOW` badge (`errorContainer` #FFDAD6 fill / `onErrorContainer` #410002 text).
4. Validation error text under a booking-form field.

### Warning (`#E65100` tertiary) — one permitted use

The **double-booking warning** (D-14) only: `tertiaryContainer` #FFE0B2 fill / `onTertiaryContainer` #BF360C text on the inline warning strip inside the booking sheet, plus a 16px `alert-circle-outline` icon in `#E65100`. Reuses the existing `OfflineBanner` warning-strip visual language (`apps/mobile/src/features/queue/components/OfflineBanner.tsx`). Do **not** use warning orange for slot availability, appointment status, or vet identity.

### Vet identity palette (D-23) — bounded categorical encoding

D-23 requires the all-vets calendar to be "color-coded/labeled per vet". A categorical palette is **not** part of the 60/30/10 budget and is therefore hard-scoped:

| Slot | Hex | Web token | Contrast on `#FFFBF5` |
|------|-----|-----------|----------------------|
| vet-1 | `#1565C0` | `--vet-hue-1` | 6.5:1 (AA normal text) |
| vet-2 | `#6A1B9A` | `--vet-hue-2` | 8.7:1 |
| vet-3 | `#00695C` | `--vet-hue-3` | 6.2:1 |
| vet-4 | `#AD1457` | `--vet-hue-4` | 6.7:1 |
| vet-5 | `#4E342E` | `--vet-hue-5` | 10.9:1 |

Add as `vetColors` in a new `packages/ui/src/theme/vetColors.ts`, exported through `theme/index.ts`, and regenerate `portal.css`. Assign deterministically by sorting the clinic's vets by `id` and indexing; **cycle after 5**.

**Hard rules — the checker will verify these:**

- These 5 hues are **deliberately not** existing semantic tokens, so vet identity can never be mistaken for status, warning, or CTA.
- Permitted uses: (a) a **4px left rail** on an appointment card/block, (b) a **8px legend dot** in the vet filter bar, (c) the border of the vet-initials chip. Nothing else.
- **Never** a fill, a background, a text colour, a badge, or a CTA.
- **Never colour-alone.** Every appointment block also carries the vet's initials in a `surfaceVariant` chip with `onSurfaceVariant` 12px text (colour-blind and monochrome-print safe).
- Solo-vet clinics (the primary persona): the rail and the initials chip are **hidden entirely** when the clinic has exactly one vet. Zero chroma cost for the majority case.

## Copywriting Contract

Voice: plain, direct, India-English, no exclamation marks, no "Oops". Verb + noun on every action. Times render as `2:30 PM` (`en-IN`, `hour12: true`) matching `QueueCardItem.formatTime`. Dates render as `Tue, 18 Aug`.

**No generic labels.** `Submit`, `OK`, `Cancel` (standalone), `Save`, `Click Here`, `Yes`, `No` are forbidden as button labels anywhere in this phase. Every button names its own outcome — including the safe/default option in a confirmation dialog (`Keep Appointment`, not `Cancel`). "Cancel" may appear only as a *verb applied to a named object* (`Cancel Appointment`, `Cancel All 6`).

### Primary actions

| Element | Copy | Placement |
|---------|------|-----------|
| **Primary CTA (mobile)** | **Book Appointment** | FAB, bottom-right, `primary` fill, `plus-circle` icon, `customSize={56}`, `borderRadius: 16`, offset 16px — mirrors the Queue "Check In" FAB exactly |
| **Primary CTA (web)** | **New Appointment** | Top-right of page header, `primary` filled button, 44px min height |
| Booking sheet confirm | **Confirm Booking** | `primary` filled, full-width, bottom of sheet |
| Booking sheet dismiss | **Discard Booking** | Text button, `onSurfaceVariant`, left of confirm. Names the outcome so the user is never guessing what "Cancel" cancels (the sheet, or the appointment they are looking at). Closes the sheet and drops the in-progress form |
| Reschedule action | **Move Appointment** | Outlined button in appointment detail |
| Check-in action | **Check In Now** | Outlined button on an `EXPECTED`/`SCHEDULED` appointment |
| Availability entry point | **Edit Availability** | List row in Settings (dedicated screen — adopting `08-RESEARCH.md` A6) |
| Add a block | **Block Time** | Secondary button on the Availability screen |
| Web notification opt-in | **Turn On Alerts** | Inline dismissible strip, not a modal (A6: foreground-only browser `Notification`) |

### Empty states

| Situation | Heading | Body |
|-----------|---------|------|
| Day agenda, no appointments (mobile) | No appointments today | Tap Book Appointment to schedule one, or open Queue for walk-ins. |
| Week grid, no appointments (web) | No appointments this week | Click any open slot to book, or use New Appointment. |
| Filtered to one vet, none booked | No appointments for Dr. {name} on {date} | Clear the vet filter to see the whole clinic. |
| Vet not working this day (D-01 closed / override) | Dr. {name} is not working on {date} | Pick another date, or change this in Settings → Edit Availability. |
| No offerable slots for the chosen service (D-02) | No open slots for {service} on {date} | Try another date, or choose a shorter service. |
| Availability screen, never configured | No working hours set yet | Set your weekly hours so staff can book appointments against your calendar. |
| No blocked periods on a day | No blocked time on {date} | Add lunch or a meeting so those slots aren't offered. |
| MOVE requests inbox empty | No move requests | Owners who ask to reschedule over WhatsApp will show up here. |

Every empty state uses `@breeyo/ui` `EmptyState` (mobile) or its web equivalent: `heading2` 28px title, `body` 16px description, centred, 32px padding — no illustration asset in Phase 8 (none exists; do not commission one).

### Loading states

| Surface | Treatment |
|---------|-----------|
| Day agenda first load | `SkeletonLoader` (`@breeyo/ui` molecule) — 4 rows at 80px height, `md` gap, shimmer `--duration-skeleton-shimmer` (1500ms) |
| Week grid first load | Grid chrome (gutter + day headers + hairlines) renders immediately; cell area shows 6 skeleton blocks |
| Slot list inside booking sheet | `ActivityIndicator` + caption "Finding open slots…" |
| Any mutation in flight | Button enters `loading` state, label unchanged, sheet stays open, form stays interactive-disabled |

Never show a full-screen spinner over already-rendered calendar data — refetches are silent (React Query `isRefetching`), matching `QueueScreen`.

### Error states

| Situation | Copy | Recovery |
|-----------|------|----------|
| Calendar failed to load (mobile) | Could not load the calendar. Pull down to try again. | Pull-to-refresh (verbatim match to `QueueScreen` error copy) |
| Calendar failed to load (web) | Could not load the calendar. | **Try Again** outlined button |
| Booking failed, slot no longer open (`SLOT_TAKEN`) | That slot was just taken. Pick another time. | Sheet stays open, slot list refetches automatically |
| Past booking horizon (`BOOKING_HORIZON_EXCEEDED`, 90 days per research A-note) | Appointments can only be booked up to 90 days ahead. Pick an earlier date. | Inline under the date field |
| Slot falls in a blocked period (D-05/D-06) | {reason} is blocked from {start} to {end}. Pick another time. | Inline; blocked band is also visibly struck on the grid |
| Vet closed that day | Dr. {name} is not working then. Pick another date or another vet. | Inline under the vet field |
| Blocked period overlaps an existing one | This overlaps an existing blocked period. Adjust the times. | Inline under the time fields |
| "Other" reason chosen with no text (D-06) | Add a short reason. | Inline under the free-text field |
| Invalid time range | End time must be after start time. | Inline |
| Offline (mobile) | You are offline. Schedule may be outdated. | Reuse `OfflineBanner` verbatim pattern; disable **Book Appointment** FAB (`#CAC4D0` fill), matching `QueueScreen`'s `fabDisabled` |
| Socket disconnected (web) | Live updates paused. Reconnecting… | Caption strip under the page header, `surfaceVariant` fill; clears silently on reconnect |

### Warnings (not errors)

| Situation | Copy | Buttons |
|-----------|------|---------|
| **Double booking (D-14)** | Dr. {name} already has {pet} at {time}. You can still book this slot. | **Book Anyway** (`primary`) / **Pick Another Time** (outlined) — inline `tertiaryContainer` strip inside the sheet, shown *before* confirm; never a blocking modal, never a hard block |
| Recurrence would exceed the horizon (D-22) | Only {n} of {total} repeats fit within 90 days. The rest were not created. | **none** — informational `showToast` (`type: 'info'`) fired after the series is created; auto-dismisses on the standard toast timeout (`toastExit` 100ms). No acknowledgement button, because there is nothing for the user to decide — the appointments that fit are already booked |
| Booking a slot in the past | That time has already passed. Book a future slot. | Inline; confirm disabled |

### Destructive confirmations

Mobile uses `Alert.alert` (matching `QueueScreen.handleNoShow`); web uses the `Modal` organism equivalent. Destructive button is `error` #BA1A1A; the safe option is always listed first and is the default. **Every safe option names what it preserves** — never a bare "Cancel", which is ambiguous in a dialog that is itself about cancelling something.

| Action | Title | Body | Buttons |
|--------|-------|------|---------|
| **Cancel appointment** | Cancel this appointment? | {pet} at {time} on {date} will be cancelled. {owner} gets a WhatsApp update. | Keep Appointment / **Cancel Appointment** (destructive) |
| **Cancel a recurring series (D-22)** | Cancel repeat appointments? | This is 1 of {n} repeats for {pet}. | Keep All / Cancel This One / **Cancel All {n}** (destructive) |
| **Mark no-show** | Mark as No-show? | This patient will be removed from the active queue. | Keep in Queue / **Mark No-show** (destructive) — Phase 3's title and body reused verbatim; the safe label is `Keep in Queue` (Phase 3's bare "Cancel" is not carried forward, and Phase 3's dialog should be updated to match when that screen is next touched) |
| **Remove blocked period** | Remove this blocked period? | {reason}, {start} to {end} on {date}. Those slots become bookable again. | Keep Blocked Time / **Remove** (destructive) |
| **Mark a day off with appointments already booked** | {n} appointments already booked on {date} | Marking this day off will not cancel them. Move or cancel them first. | Go Back / **Mark Day Off Anyway** (destructive) |
| **Clear weekly availability** | Clear weekly hours? | Staff will not be able to book appointments for Dr. {name} until you set hours again. | Keep Hours / **Clear Hours** (destructive) |

### Push notification copy (D-27 — Claude's discretion per CONTEXT.md)

Staff-only (D-26). Title ≤ 40 chars, body ≤ 120 chars. Each carries `data.deepLink` for Expo notification routing.

| Trigger | Title | Body | Deep link |

MOVE requests also write a `Notification` row (`module: 'scheduling'`, `type: 'MOVE_REQUEST'`, `data: { appointmentId }`) rendered by the **existing** `NotificationList` organism and counted by `NotificationBadge` — adopting `08-RESEARCH.md` Open Question 3's recommendation. **Do not build a new task-tracking surface.**

## Layout & Interaction Contracts

### Appointment card/block anatomy (both surfaces, one information hierarchy)

Fixed order, top to bottom / left to right:

1. **Vet rail** — 4px, `vetColors[i]`, full height, left edge. Hidden when clinic has one vet.
2. **Time** — caption 12px `onSurfaceVariant`: `2:30 PM` (mobile agenda shows `2:30 – 2:45 PM`).
3. **Pet name** — 16px weight 500 `onSurface`, `numberOfLines={1}`.
4. **Owner name** — 16px weight 400 `#5D4037` (matching `QueueCardItem.ownerName`), `numberOfLines={1}`.
5. **Service** — caption 12px `onSurfaceVariant`, e.g. `Vaccination · 15 min`.
6. **Multi-pet indicator (D-21)** — when >1 pet: caption `+{n} more pets` and a `paw` icon; pet names listed in the drawer/sheet, never on the card.
7. **Vet initials chip** — `surfaceVariant` fill, 1px `vetColors[i]` border, 12px `onSurfaceVariant` text (`DR`, `RS`). Hidden for solo-vet clinics.
8. **Status badge** — right-aligned; omitted for `SCHEDULED` (see rule above).
9. **Recurrence marker (D-22)** — 12px `repeat` icon, `outline` colour, next to the time.

Card: `background` fill, `borderRadius: 12` (`lg`), `md` padding, `elevation.level1`, `minHeight: 80` — identical to `QueueCardItem`. `CANCELLED` cards render at `opacity: 0.5` with the pet name struck through (matching the existing `disabled` treatment).

### Mobile day agenda (D-24, SCH-03)

- Screen title `Schedule` (heading 28px), 16px horizontal / 16px top padding — matches `QueueScreen.title`.
- Order: title → `OfflineBanner` → `DateNavigator` → `VetFilterBar` → agenda `SectionList` → `Book Appointment` FAB.
- Sections are **time-of-day groups**: `Morning` (before 12 PM) / `Afternoon` (12–5 PM) / `Evening` (5 PM onward). Empty groups are omitted entirely.
- Within a group, sorted ascending by scheduled time. Past appointments on today's date render at `opacity: 0.6`; `NowIndicator` sits between the last past and first future row.
- Pull-to-refresh (`onRefresh` / `refreshing`), `contentContainerStyle: { paddingBottom: 100 }` for FAB clearance — verbatim `QueueBoard` pattern.
- Blocked periods (D-05) render as a full-width `surfaceVariant` strip, 44px, caption text `Lunch · 1:00 – 2:00 PM`, no interaction.
- Swipe left on a row → reveal **Cancel Appointment** (destructive). Swipe right → **Check In**. Both also reachable by tap → quick sheet (never gesture-only).

### Web week grid (D-25, SCH-03)

- Page: `background` fill, `xl` (32px) gutter, `<h1>Schedule</h1>` heading 28px, `New Appointment` top-right.
- Layout: `[56px time gutter][7 equal day columns, min-width 96px each]`. Horizontal scroll below 800px viewport width — no responsive reflow to a day view (mobile is the day surface).
- **Row = 30 minutes = 64px (`5xl`).** Rows span the union of all displayed vets' open hours for the week, ±1 hour of padding.
- **No sub-row proportional sizing in v1.** An appointment shorter than 30 minutes still occupies a full 64px row, with its true duration in the service line (`Vaccination · 15 min`). Rationale: a proportionally-sized 15-minute block would be 32px tall — below the 44px target and too small for the pet name. Honest and readable beats geometrically exact for the web app's first screen.
- Appointments longer than 30 minutes span `ceil(duration / 30)` rows.
- Double-booked appointments (D-14) render **side by side** within the cell, each at `50%` width (max 3 shown; a 4th+ collapses to a `+{n}` chip opening the drawer).
- Sticky day-header band: `surfaceVariant` fill, 48px (`3xl`), 16px weight-500 `Tue 18`. Today's column header carries a 2px `primary` underline and its date number is `primary`.
- Time gutter: `surfaceVariant`, right-aligned caption 12px `onSurfaceVariant`, labels on the hour only (`9:00 AM`), half-hour rows unlabelled.
- Grid hairlines: 1px `outlineVariant` #CAC4D0 on the hour, `surfaceVariant` on the half-hour.
- Non-working and blocked cells (D-01/D-05): `surfaceVariant` fill, `cursor: not-allowed`, `aria-disabled="true"`, no hover.
- Empty bookable cell: `background` at rest → `surfaceVariant` on hover with a centred 16px `plus` glyph in `onSurfaceVariant`; click opens `BookAppointmentDrawer` pre-filled with that day, time, and (if filtered) vet.
- "Now" line: 2px `primary` horizontal rule across today's column only, with an 8px `primary` dot at the gutter edge; repositions every 60 s.
- `VetLegend` sits under the header: 8px `vetColors[i]` dot + vet name, click to filter, "All Vets" default (D-23).

### Booking flow (SCH-01) — identical steps on both surfaces

`BottomSheet` on mobile (`snapPoints: ['50%', '90%']`), 400px right drawer on web.

1. **Find the owner (D-19)** — mobile-number `TextInput`, `keyboardType="phone-pad"`, `maxLength={10}`, placeholder `Enter 10-digit mobile number`, `phone` left icon. Verbatim reuse of `CheckInSheet`'s field.
2. **Pick pets (D-21)** — multi-select rows of that owner's pets with species icon + name. Not found → `New patient` row → inline registration, matching `CheckInSheet`.
3. **Pick service (D-02)** — `ListItem` rows from the service catalog; each shows `{service} · {n} min`. Selecting a service sets the slot duration.
4. **Pick vet (D-04)** — `Chip` row; pre-selected when the calendar is filtered. Hidden for solo-vet clinics.
5. **Pick date** — native date picker, capped at **today + 90 days** (D-07); dates past the cap are disabled, not hidden.
6. **Pick slot** — chip grid of offerable slots for `(vet, date, duration)`. Already-taken slots are **shown, not hidden** (D-14 / research A4), styled `surfaceVariant` fill with a 12px `alert-circle-outline` in `#E65100` and `aria-label="{time}, already booked"`. Selecting one reveals the double-booking warning strip.
7. **Repeat (D-22, optional, collapsed by default)** — `AccordionItem` "Repeat this appointment"; inside: `Every week` / `Every 2 weeks` / `Every 4 weeks` + `Number of times` stepper (2–12). Live preview caption: `{n} appointments through {last date}`.
8. **Confirm** — `Confirm Booking`, full-width `primary`. Disabled until owner + ≥1 pet + service + date + slot are all set. Enters `loading` on submit; sheet stays open until success, then closes and toasts. The paired dismiss button is `Discard Booking` (see § Primary actions) — never a bare "Cancel".

Progressive disclosure: each step reveals only after the prior one resolves. Never render an empty slot grid before a service is chosen — show the caption `Pick a service to see open slots.`

### Real-time sync (SCH-04)

- Both surfaces subscribe to the existing `clinic:{clinicId}` Socket.IO room; events invalidate React Query keys (mobile mirrors `useQueueSocket.ts`).
- **Remote changes never move the viewport.** A remote insert animates in over `--duration-expand-collapse` (200ms) with an opacity fade; the user's scroll position, open sheet, and in-progress form are untouched.
- A remotely-cancelled appointment the user has open in a drawer/sheet shows an inline `surfaceVariant` strip: `This appointment was just cancelled by someone else.` and disables its action buttons — it does **not** auto-close.
- Status changes animate the badge over `--duration-status-badge-update` (300ms).
- Web reconnect: no toast, no spinner — only the header caption strip described in § Error states.

### Motion

Use only `packages/ui/src/theme/animation.ts` durations. Everything below 250ms; no bounce, no spring, no parallax.

| Interaction | Duration token | Value |
|-------------|----------------|-------|
| Card/chip press feedback | `microFeedback` | 100ms |
| Sheet/drawer open + close | `screenTransition` | 250ms |
| Accordion (repeat section) expand | `expandCollapse` | 200ms |
| Remote appointment appear/disappear | `expandCollapse` | 200ms |
| Toast in / out | `toastEnter` / `toastExit` | 150 / 100ms |
| Status badge change | `statusBadgeUpdate` | 300ms |
| Skeleton shimmer | `skeletonShimmer` | 1500ms |
| Date/week navigation | none — instant | — |

Honour `prefers-reduced-motion` on web (fades only, no transforms) and RN `AccessibilityInfo.isReduceMotionEnabled()` on mobile.

### Accessibility

- Every interactive element ≥ 44 × 44px.
- Every appointment card/block carries `accessibilityLabel` / `aria-label`: `{time}, {pet}, {owner}, {service}, with Dr. {vet}, {status}` — following `QueueCardItem`'s existing label pattern.
- Web grid uses `role="grid"` / `role="row"` / `role="gridcell"`; day headers are `<th scope="col">`. Arrow keys move cell focus; `Enter` books the focused cell; `Escape` closes drawer.
- Status and vet identity are **never** communicated by colour alone — status always has a text label, vet always has initials.
- Every icon-only control has a text `accessibilityLabel` (`Previous day`, `Next day`, `Filter by vet`).
- Button labels are self-describing out of context, so a screen-reader user hearing only the button name knows the outcome (`Discard Booking`, `Keep in Queue`, `Cancel Appointment`) — this is the accessibility reason the generic-label ban above is a hard rule, not a style preference.
- All new copy strings go through i18n (`packages/ui/src/i18n/locales/{en,hi}/common.json`) under a new `scheduling` namespace, matching the existing `queue` / `portal` namespaces. Hindi values may initially mirror English, but the keys must exist.
- Body text contrast: `#1C1B1F` on `#FFFBF5` ≈ 15.8:1; muted `#49454F` on `#FFFBF5` ≈ 8.3:1; `#79747E` on `#FFFBF5` ≈ 4.6:1 — reserve `#79747E` for 12px+ non-essential text only (grid hairlines, timestamps).
