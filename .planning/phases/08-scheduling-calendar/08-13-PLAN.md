<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff editor → availability write | A staff member changes which times any client can book, for a vet who may not be themselves |
| HH:MM editor state → minutes-based API payload | A representation change sits between what the user sees and what the server stores |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-67 | Elevation of Privilege | editing another clinic's vet's availability by supplying their `vetId` | mitigate | The vet picker is populated only from `GET /scheduling/vets`, which is clinic-scoped, and plan 08-05's service independently verifies the `vetId` is a member of the JWT's clinic and returns `404 VET_NOT_FOUND` otherwise; the client's picker is an affordance, not the control |
| T-08-68 | Tampering | a malformed or inverted time reaching the slot-generation arithmetic | mitigate | `toTemplatePayload` and `toBlockedPeriodPayload` validate through the shared `hhmmToMinutes`, which throws on anything outside `HH:MM` in 00:00 to 23:59, and reject `close <= open`; the server re-validates with Zod bounds and its own cross-field rules |
| T-08-69 | Availability | a vet clearing their hours and silently making the clinic unbookable | mitigate | `Clear Hours` is guarded by a destructive `Alert.alert` whose body states the consequence explicitly, and the safe option `Keep Hours` is listed first and default |
| T-08-70 | Availability | marking a day off that already has appointments, orphaning them | mitigate | The override write intentionally succeeds server-side (plan 08-05) and returns `affectedAppointmentCount`; the client then requires an explicit `Mark Day Off Anyway` confirmation and reverts the override if the user backs out, so the appointments are never silently stranded |
| T-08-71 | Repudiation | an availability change with no record of who made it | mitigate | Every availability write is audit-logged server-side with `AuditEvent.AVAILABILITY_UPDATED` or the blocked-period events plus the `vetId` in `metadata` (plan 08-05) |
</threat_model>
