# Phase 4 -- UI Design Contract

> Visual and interaction contract for EMR and Clinical Records. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase is the clinical heart of Breeyo -- it transforms the queue management tool into a full veterinary practice management system. All tokens, base components, and interaction patterns from 02-UI-SPEC.md are inherited and NOT re-declared here. Phase 3 feature components (QueueCardItem, PetProfileScreen, VisitTimeline) are consumed where applicable. This document specifies what Phase 4 adds or refines for the consultation workflow, SOAP notes, prescriptions, voice-to-text, PDF generation, vaccination/deworming tracking, and medical history.

## Spacing Scale

Inherited from Phase 2 UI-SPEC (8px base unit). No modifications.

| Token | Value | Phase 4 Usage |
|-------|-------|---------------|
| `spacing.xs` | 4px | Icon-to-label gap in floating action bar, chip internal padding, vitals unit suffix gap |
| `spacing.sm` | 8px | SOAP section compact field gaps, quick-pick chip spacing, body system checklist item gaps, prescription list item internal spacing |
| `spacing.md` | 16px | Accordion section internal padding, form field gaps within SOAP sections, patient banner internal padding, prescription card padding |
| `spacing.lg` | 24px | Gap between accordion sections when expanded, review screen section spacing, PDF section margins |
| `spacing.xl` | 32px | Screen-level horizontal margins, gap between major screen regions (banner vs accordion vs floating bar) |
| `spacing.2xl` | 40px | Vertical gap above floating quick-action bar region |
| `spacing.3xl` | 48px | Bottom padding above floating bar safe zone |

Exceptions:
- **Touch targets**: 44x44pt minimum enforced on all accordion headers, floating bar icons, chip selectors, drug search results, body system toggles (Phase 2 standard).
- **Patient banner height**: 56px (compact sticky header with pet name, species, age, weight, owner info -- D-02).
- **Floating quick-action bar height**: 56px (matches FAB standard diameter -- D-10). Positioned 16px above bottom edge, centered horizontally.
- **Accordion section header height**: 48px minimum (tap target + section title + expand/collapse chevron).
- **Drug search modal**: Full-screen modal on mobile. Search input 48px height. Drug result rows 56px height (balanced density for scannable drug list).
- **Vitals input row height**: 48px per vital field (compact density per Phase 2 EMR Information Density rules).

### Vitals Range Color Map

| Range Status | Text Color | Border/Indicator Color | Background |
|-------------|-----------|----------------------|------------|
| Normal | `primary` (#2E7D32) | `primary` (#2E7D32) | none (transparent) |
| Slightly abnormal | `tertiary` (#E65100) | `tertiary` (#E65100) | `tertiaryContainer` (#FFE0B2) at 30% opacity |
| Critically abnormal | `error` (#BA1A1A) | `error` (#BA1A1A) | `errorContainer` (#FFDAD6) at 30% opacity |

Threshold logic: "Slightly abnormal" is within 10% of the species normal range boundary. "Critically abnormal" is beyond 10% of the boundary. Example: dog temp normal 38.0-39.2 C. A reading of 39.5 C is slightly abnormal. A reading of 40.5 C is critically abnormal.

## Interaction Contracts

### Consultation Entry from Queue (Claude's Discretion: tap-to-open)

```
Vet taps "Call Next" or taps a WAITING patient card
  |
  v
Queue entry status changes to IN_CONSULT (Phase 3)
  -> Toast: "[Pet Name] called into consultation"
  -> Queue card now shows "In Consult" badge + "with [Vet Name]"

Vet taps the IN_CONSULT queue card (or resume banner)
  |
  v
ConsultationScreen opens
  -> Check for existing draft: if found, resume
  -> If no draft, create new consultation with visit type selector
  -> Patient banner populates from pet/owner data
  -> All accordion sections collapsed by default
  -> Vitals section auto-expands on first open
```

Rationale for tap-to-open (not auto-open on Call Next): vets may Call Next while finishing notes on the previous patient. Auto-opening would interrupt. The In Consult card serves as a clear entry point when the vet is ready.

### Resume Flow (Claude's Discretion: resume banner)

```
If vet navigates away from consultation (back to queue, app background, etc.)
  and consultation is still IN_CONSULT status (not finalized):
  |
  v
Queue screen shows resume banner at top:
  "[Pet Name] has a consultation in progress. Tap to resume."
  Background: primaryContainer (#C8E6C9)
  Placement: Below navigation bar, above queue sections
  |
  v
Vet taps banner -> ConsultationScreen reopens with draft state restored
```

### Accordion Section Navigation (D-01)

```
Consultation screen loads:
  -> Visit type selector visible at top (below patient banner)
  -> All 7 accordion sections listed in fixed order:
     Vitals -> Subjective -> Objective -> Assessment -> Plan -> Prescriptions -> Files
  -> First section (Vitals) auto-expands
  -> Only 1 section expanded at a time (collapse previous when new opens)
  |
  v
Vet taps accordion header:
  -> 200ms expand/collapse animation (Phase 2 timing)
  -> Previously expanded section collapses
  -> Tapped section expands
  -> Screen auto-scrolls to show expanded section content
  |
  v
Exception: Vet can keep multiple sections open by tapping "pin" icon
  on section header (optional -- Claude's Discretion: NOT implemented for Beta;
  single-expand is simpler and sufficient)
```

### Auto-Save Draft (D-05)

```
Vet makes any change in any section:
  -> isDirty flag set to true in Zustand store
  -> DraftIndicator shows "Unsaved changes" (tertiary dot)
  -> 3-second debounce timer starts
  |
  v
After 3 seconds of inactivity:
  -> API PATCH /api/v1/consultations/{id}/draft
  -> DraftIndicator updates to "Draft -- auto-saved [HH:MM]"
  -> isDirty reset to false
  |
  v
If vet taps "End Consultation" while dirty:
  -> Cancel pending auto-save timer
  -> Synchronous save of current state
  -> Then proceed to review screen
```

### End Consultation Flow (D-04, D-08, D-09)

```
Vet taps "End Consultation" button:
  |
  v
Cancel any pending auto-save. Save current draft synchronously.
  |
  v
Navigate to ConsultationReviewScreen:
  -> Display all sections as read-only summary
  -> Sections with no data show "Not recorded"
  -> "Edit" text button returns to consultation screen
  -> "Confirm & Finalize" filled button at bottom
  -> Warning: "Once finalized, this record cannot be edited."
  |
  v
Vet taps "Confirm & Finalize":
  -> Optional: FollowUpSheet appears (D-09)
     -> Vet picks date + reason, or taps "Skip"
  -> API POST /api/v1/consultations/{id}/finalize
  -> Button shows spinner during finalization
  -> Consultation status: draft -> finalized
  -> Queue entry status: IN_CONSULT -> DONE (via Phase 3 queue API)
  -> Consultation duration auto-calculated (D-13)
  -> Vitals weight auto-updates pet profile (D-14)
  -> Toast: "Consultation finalized"
  -> Navigate back to queue screen
```

Vet taps "Add Medication" in Prescription section (or Rx icon in floating bar):

DrugSearchModal opens (full-screen):

## N/A Toggle per SOAP Section (Claude's Discretion)

NOT implemented for Beta. Every section is always present. Rationale: with accordion collapsed by default, untouched sections have zero cognitive cost. An N/A toggle adds UI complexity without meaningful time savings. If a section is irrelevant, the vet simply does not expand it.

---

## Additional Vitals (Claude's Discretion)

For Beta, only the 4 core vitals (D-22): weight, temperature, heart rate, respiratory rate. Body Condition Score (BCS) and other additional vitals deferred to post-Beta. Rationale: the 4 core vitals cover the vast majority of consultations. BCS requires a visual reference scale that adds UI complexity.

---

## Surgery Template Specific Fields (Claude's Discretion)

For Beta, the Surgery template uses the same SOAP structure as General Consultation but with surgery-specific quick-pick chips in the Subjective and Objective sections (D-16). No additional structured surgical fields (anesthesia type, incision site picker, etc.) -- SOAP free-text handles surgical details. Rationale: structured surgical fields require significant clinical domain modeling; free-text + chips is sufficient for Beta.

---

## Recording UI Indicator (Claude's Discretion)

Minimal overlay approach: pulsing tertiary dot + "Recording..." text positioned near the active text field (not a full-screen overlay). Rationale: full overlay blocks the vet from reading existing content in other sections while dictating. Minimal indicator keeps context visible.

---

## SOAP Quick-Pick Chips Behavior (Claude's Discretion)

Quick-pick chips are visible by default when a SOAP section is expanded. Chips wrap to multiple lines (no horizontal scroll). Selected chips show `primaryContainer` (#C8E6C9) background. Tapping a selected chip deselects it. "Add custom" chip (with + icon) at end of each chip group opens a small text input to add a custom term. Custom terms persist per vet for future visits (D-17). Chips do NOT collapse -- they are always visible within their section. Rationale: chips ARE the speed optimization; hiding them defeats the purpose.

---

## Drug Database Admin (Claude's Discretion)

For Beta, no admin UI for drug database management. Drug data is pre-seeded via database migration (200-300 drugs). Updates require a code deploy or database migration. Rationale: an admin UI for drug management is a separate feature with its own UX needs (search, edit, batch import). Pre-seeded data covers Beta needs. Post-Beta, a settings screen in the web dashboard (Phase 9) can expose drug management to clinic admins.
