Finish Wave 0c (D-30): convert the last two clinic-scoped modules, document the three legitimate admin-client consumers, and lock the whole thing behind a CI gate.

Split from plan 06-02, which converted patient, queue, emr, attachment, vaccination and drug across its first two tasks. Purpose: the same phase-wide tenancy foundation plan 06-02 serves. Every Phase 6 requirement sits on top of it, which is why the requirement list is the full set.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated HTTP request → repository query | The clinic identity carried in the JWT must constrain every row the query can reach |
| background job / cron → database | No request context exists; tenancy must come from the job payload and is not RLS-enforced |
| future code change → tenancy boundary | A new module added in a later phase must not be able to silently bypass RLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-133 | Information Disclosure | notification and clinic route modules using the RLS-bypassing admin client | mitigate | Per-request `buildService(request.db)` construction, following plan 06-02's reference implementation |
| T-06-134 | Information Disclosure | a future module reintroducing the admin client into a route file | mitigate | `scripts/check-tenant-client.sh` invoked as a blocking CI step; the gate is deliberately written after the conversion lands so it needs no temporary allowlist |
| T-06-26 | Information Disclosure | BullMQ notification worker with no request context | accept | Workers derive `clinicId` from the durable job payload written by an already-tenant-scoped request; documented as a `D-30 exemption` comment and whitelisted in the gate rather than silently permitted |
| T-06-135 | Elevation of Privilege | `PermissionService` on the admin client being mistaken for an oversight and "fixed" into `request.db`, breaking login | accept | Inline `D-30 exemption` comment stating it runs before `tenantContext`; the gate's allowlist encodes the same fact so a well-meaning change fails CI rather than production login |
| T-06-136 | Tampering | a self-invalidating gate whose own header prose satisfies its grep | mitigate | Comment-only lines are stripped before matching; `bash -n` and a deliberate injection test are both acceptance criteria |
</threat_model>
