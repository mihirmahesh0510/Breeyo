<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public owner portal route → owner-facing UI | Unauthenticated visitors render token-scoped content in the browser |
| Portal checkout handoff → external Razorpay page and return | Owner leaves the trusted portal shell and returns with payment state changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-16 | Information Disclosure | Portal invalid/expired states | mitigate | Render distinct `ExpiredLinkState` and invalid no-data state; never hydrate protected data for invalid tokens |
| T-09-17 | Spoofing | Payment return UX | mitigate | Read return state from the server-backed checkout/session flow and show explicit success/failure/interrupted banners before any navigation |
| T-09-18 | Denial of Service | Mobile portal performance | mitigate | Add Lighthouse mobile-4G budget config and keep the portal shell focused on trust, records, and invoice UI without heavyweight dashboard chrome |
| T-09-19 | Repudiation | Human portal acceptance | mitigate | Require explicit human verification of valid, invalid, expired, and payment-return states before calling the plan complete |
</threat_model>
