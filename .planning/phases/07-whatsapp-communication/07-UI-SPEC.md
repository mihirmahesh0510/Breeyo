# Phase 7 — UI Design Contract

> Visual and interaction contract for WhatsApp Communication. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | React Native Paper v5 (MD3); shadcn not applicable |
| Preset | not applicable |
| Component library | Phase 2 `@breeyo/ui` React Native Paper + custom compound components |
| Icon library | `@expo/vector-icons` MaterialCommunityIcons + existing veterinary SVG pattern |
| Font | Mobile system default: Roboto on Android, SF Pro on iOS |

Phase 7 is **mobile app only**. Do not build a web dashboard surface in this phase. The central UI is a WhatsApp-style staff inbox and owner-thread view, not a developer console. Access is limited to Front Desk and Admin.

Codebase scan on 2026-05-06 found **no** `components.json`, `tailwind.config.*`, `postcss.config.*`, `package.json`, or app source files under `src/`, `apps/mobile/src/`, or `apps/web/src/`. This contract therefore inherits the approved Phase 2 mobile design system rather than an implemented repo-local component setup. shadcn initialization gate is **not applicable** for this Phase 7 mobile-only React Native surface.

Required screen surfaces:
- `WhatsAppInboxScreen`: owner-thread list keyed by owner mobile number.
- `WhatsAppThreadScreen`: chat-like conversation history with message bubbles, status badges, attachments, and contextual action cards.
- `TemplateSendSheet`: context-send bottom sheet launched from invoice detail, pet profile, reminder cards, booking records, and document views.
- `WhatsAppConfigScreen`: Admin-only simulator/provider settings, clinic hours, slot length, reminder defaults, deterministic failure controls.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Bubble metadata gaps, icon-to-status gaps, compact badge padding |
| sm | 8px | Message bubble internal vertical padding, quick-reply gaps |
| md | 16px | Screen horizontal padding, thread row padding, bottom sheet padding |
| lg | 24px | Section padding, empty/error state spacing |
| xl | 32px | Layout gaps between filter bar, list, and footer actions |
| 2xl | 48px | Major section breaks and empty state illustration spacing |
| 3xl | 64px | Page-level spacing and bottom tab safe area compensation |

Exceptions:
- Touch targets: 44x44pt minimum for thread rows, quick replies, retry buttons, action cards, and template-send controls.
- Chat bubbles: max width 78% of screen; 12px horizontal internal padding is allowed to match chat density while staying multiple-of-4.
- Thread rows: minimum 72px height for owner name, mobile number, last message, timestamp, and status/needs-action indicator.
- Bottom sheet drag handle: 32px wide x 4px high.

## Typography

Phase 7 uses the Phase 2 type system but limits active sizes to four roles for chat readability.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 500 | 1.33 |
| Heading | 20px | 500 | 1.2 |
| Display | 28px | 400 | 1.29 |

Rules:
- Use only Regular 400 and Medium 500.
- Message body text is 16px/1.5; never reduce message text below 16px.
- Timestamps, mobile numbers, status metadata, and failure reasons use 12px labels.
- Screen title uses 28px; thread owner title and bottom sheet titles use 20px.

## Color

Use the Phase 2 warm MD3 palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFBF5` | Screen background, thread background, bottom sheet surface |
| Secondary (30%) | `#F5F0EB`, `#D7CCC8`, `#C8E6C9` | Thread rows, incoming bubbles, filter chips, cards, input-like preview surfaces |
| Accent (10%) | `#2E7D32`, `#E65100` | Outgoing bubbles, primary CTAs, active filters, needs-action dots, warning/failure attention markers |
| Destructive | `#BA1A1A` | Cancel booking, STOP opt-out warning, failed status, invalid number, destructive confirmations only |

Accent reserved for:
1. Primary green `#2E7D32`: outgoing message bubbles, primary CTA buttons (`Send Template`, `Retry Message`, `Confirm Booking`), active filter chip, delivered/success status icon, WhatsApp preference toggles ON.
2. Orange `#E65100`: unread/needs-action dots, pending queued badge, delayed delivery warning, reminder due attention card, retry-state indicator.
3. Destructive red `#BA1A1A`: failed badge, invalid number warning, opt-out/STOP state, cancel booking confirmation, failure reason icon.

Do not use accent colors for decorative chat backgrounds, body text, dividers, or non-action labels.

## Copywriting Contract

Tone: warm, concise, clinic-branded, and English-only for Beta. Staff UI copy is direct and action-oriented. Owner template copy must fit WhatsApp: short paragraphs, clear next action, no jargon.

| Element | Copy |
|---------|------|
| Primary CTA | Send Template |
| Empty state heading | No WhatsApp messages yet |
| Empty state body | Send an invoice, reminder, booking update, or clinical document to start the first owner thread. |
| Error state | Could not load WhatsApp messages. Pull down to try again. |
| Destructive confirmation | Cancel booking: Cancel this booking? The owner will see the booking as cancelled, and the reason will be saved in the thread. |

Required labels and messages:
- Inbox title: `WhatsApp`
- Filter chips: `All`, `Invoices`, `Reminders`, `Bookings`, `Failed`, `Needs action`
- Thread empty state: `No messages in this thread yet` / `Send a template from an invoice, reminder, booking, pet profile, or document view.`
- Offline banner: `You are offline. New WhatsApp actions will send when you reconnect.`
- Failed banner: `Message failed. Check the reason and retry when ready.`
- Invalid number warning: `This mobile number may not be on WhatsApp. Correct the number before retrying.`
- STOP state warning: `Owner has opted out of reminders. Transactional messages still need staff review.`
- Success toast: `Message queued`
- Retry success toast: `Retry queued`
- Resolve action toast: `Action marked resolved`

Six Beta templates must exist with these staff-facing names:
1. `Invoice delivery`
2. `Payment reminder`
3. `Follow-up reminder`
4. `Vaccine due`
5. `Deworming due`
6. `Booking confirmation`

Destructive actions in this phase:
- Cancel booking: bottom sheet confirmation; confirm button `Cancel Booking` in destructive red text, neutral button `Keep Booking`.
- STOP/disable reminders from owner preference: confirmation copy `Stop reminders for this owner? Non-essential reminders will no longer be sent.` Confirm button `Stop Reminders`, cancel `Keep Reminders`.
- Mark invalid number: confirmation copy `Mark this number invalid? Staff must correct it before WhatsApp retries.` Confirm button `Mark Invalid`, cancel `Keep Number`.

## Interaction Contract

### Inbox
- Thread list is grouped by owner mobile number, with owner name, mobile number, last message preview, latest context label, timestamp, and status.
- A thread row tap opens `WhatsAppThreadScreen`.
- Pull-to-refresh reloads threads.
- Search supports owner name, mobile number, pet name, invoice number, and booking reference.
- Filters are horizontal chips below the title; only one primary filter is active at a time.
- `Failed` and `Needs action` filters must be visually discoverable without requiring a separate task screen.

### Thread View
- Use incoming/outgoing chat bubbles with clear directionality: outgoing staff/system messages align right in green-tinted style; simulated owner replies align left on secondary surfaces.
- Each message displays timestamp and one status label: `Queued`, `Sent`, `Delivered`, `Failed`, or `Replied`.
- Failed messages show failure reason inline and expose `Retry`, `Call Owner`, and `Mark Resolved` where relevant.
- Context cards appear inline inside the thread for invoice, pet, reminder, booking, and document references.
- Scripted replies render as quick-reply/action chips; no free-text NLP input is exposed in Beta.

### Context Send Bottom Sheet
- Opened from invoice detail, pet profile, reminder cards, booking records, and document views.
- Shows recipient owner, mobile number, template name, variables preview, attachment preview if present, optional staff note, consent/preference warning, and primary CTA `Send Template`.
- Staff note is optional and cannot replace or edit the fixed template body.
- Unpaid invoice template automatically includes invoice PDF and Razorpay payment link; paid invoice omits payment CTA.

### Booking Flow Cards
- Booking conversation uses action cards for `Confirm booking`, `Cancel booking`, `Move booking`, `Call owner`, and `Mark resolved`.
- Slot selection uses simple clinic-hours slots only; do not show calendar day/week views.
- Confirmed Phase 7 bookings do not auto-enter the walk-in queue. Show helper text: `Check in manually when the owner arrives.`

### Simulator Admin Controls
- Admin can configure deterministic delivery failure, delayed delivery, and invalid-number scenarios.
- No random failures in the UI.
- Simulator channel must be labeled `Simulator` in config/log surfaces, but normal staff thread views should still feel WhatsApp-like.

## Accessibility Contract

- WCAG 2.1 AA: 4.5:1 text contrast and 3:1 UI contrast.
- Touch targets minimum 44x44pt.
- Status must never rely on color alone; pair color with text and icon.
- Message bubbles expose screen reader labels: direction, sender, time, status, and attachment/context.
- Quick replies and action cards expose `accessibilityRole="button"` and `accessibilityState` for disabled/loading states.
- Font scaling up to 1.5x must not truncate message body or action labels; metadata may wrap to a second line.
- Android hardware back returns from thread to inbox; from bottom sheet it dismisses the sheet first.
