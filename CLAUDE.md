# Breeyo - Project Instructions

## Overview

Breeyo is a mobile-first veterinary clinic management platform for solo and small-team vets in India. Monorepo with Turborepo + pnpm workspaces.

## Tech Stack

- **API:** Fastify 5 + Prisma ORM + PostgreSQL (RLS multi-tenancy)
- **Mobile:** Expo SDK 52 (React Native) + Expo Router
- **Web:** Next.js
- **UI:** React Native Paper v5 (MD3), atomic design (atoms/molecules/organisms)
- **Cache/Queue:** Redis + BullMQ
- **Validation:** Zod schemas shared via `@breeyo/validators`
- **Types:** Shared via `@breeyo/types`
- **Auth:** JWT with refresh token rotation, SMS OTP, RBAC with permission overrides
- **CI:** GitHub Actions, Node 22, pnpm 9

## Development Commands

```bash
pnpm install            # Install all dependencies
pnpm dev                # Start all apps in dev mode
pnpm build              # Build all packages
pnpm test               # Run all tests
pnpm db:migrate         # Run Prisma migrations
pnpm db:generate        # Generate Prisma client
pnpm db:seed            # Seed test data
```

Filter to a specific package:
```bash
pnpm --filter @breeyo/api test
pnpm --filter @breeyo/ui test
```

## Coding Conventions

### API (Fastify)

- Module structure: `modules/<name>/` with `controller.ts`, `service.ts`, `routes.ts`, `schema.ts`
- Routes registered via `app.register()` with `/api/v1` prefix
- Use `@fastify/jwt` for auth, `authenticate` and `authorize` middleware
- RLS enforced at database level via `prisma-rls.ts` — always set tenant context
- Error handling via centralized `error-handler.ts`
- Rate limiting: 200/min global, 20/min on auth endpoints
- All Prisma columns use `snake_case` with `@map()`, TypeScript uses `camelCase`
- UUIDs generated by PostgreSQL (`gen_random_uuid()`)
- Audit logging via `audit-log.ts` for auth events

### Mobile (Expo)

- File-based routing via Expo Router
- Secure storage via `expo-secure-store` for tokens
- Push notifications via `expo-notifications`
- Use `@breeyo/validators` for form validation (same schemas as API)

### UI Library (`@breeyo/ui`)

- Atomic design: atoms > molecules > organisms
- Design tokens in `src/theme/` (colors, spacing, typography, elevation, borderRadius, animation)
- Primary: `#1E2A6E` (navy), Secondary: `#5D4037` (brown), Tertiary: `#E65100` (orange)
- Background: `#FFFBF5` (warm white)
- i18n via `i18next` + `react-i18next`
- Wireframe stories in `src/wireframes/` with 4 states: empty, loading, populated, error
- CSS token generation: `pnpm --filter @breeyo/ui generate:css-tokens`

### General

- TypeScript strict mode across all packages
- ESM modules (`"type": "module"` in API)
- Zod for all request/response validation
- Commit messages: `feat|fix|chore|docs(phase-NN): description`
- Branch naming: `breeyo/phase-NN-description`
- Never commit `.env` files — use `.env.example` as reference

## Database

- PostgreSQL 16 with Row-Level Security for multi-tenancy
- Two DB roles: `breeyo_admin` (migrations), `breeyo_app` (app queries with RLS)
- RLS setup scripts: `prisma/init-rls-roles.sql`, `prisma/post-migrate.sql`
- See `ERD/` for entity relationship documentation

## Testing

- Vitest for all packages
- API tests use `supertest` with `buildApp({ logger: false })`
- Faker.js for test data generation
- CI runs with real PostgreSQL 16 + Redis 7

## Infrastructure

- AWS ECS task definitions in `infra/aws/`
- Staging and production deploy workflows
- Region: `ap-south-1` (Mumbai)
- Backup verification via scheduled workflow
