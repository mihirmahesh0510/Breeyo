## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public owner token URL → owner-portal services | Unauthenticated public traffic attempts to gain access through tokenized routes |
| Portal checkout/reissue endpoints → billing and WhatsApp systems | Owner-selected actions cross from public portal flows into trusted payment and messaging infrastructure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-13 | Spoofing | Magic-link validation | mitigate | Hash incoming tokens, validate against DB-backed scope on every request, and return a no-data `INVALID` envelope for tampered or mismatched links |
| T-09-14 | Information Disclosure | Portal records and invoices | mitigate | Limit projections to validated owner/pet/invoice scope and expose diagnosis + prescriptions only for EMR content |
| T-09-15 | Tampering | Checkout and reissue actions | mitigate | Re-check scope before checkout or reissue, snapshot invoice ids server-side, and delegate messaging/payment to existing trusted services rather than trusting client totals or targets |
</threat_model>
