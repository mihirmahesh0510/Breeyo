<objective>
Wave 0a (D-30, BLOCKING every other Phase 6 plan): make PostgreSQL row-level security real before any money table is created.

Today `createTenantClient` instantiates a brand-new `PrismaClient` per request and never disconnects it, and it issues `SET LOCAL app.clinic_id` as a statement separate from the query it is supposed to scope — so the GUC is not guaranteed to be live on the connection that runs the query. Separately, only 3 of 28 tables have RLS policies, an orphaned SQL file declares policies against a different GUC name (`app.current_clinic_id`) that nothing sets, and 15 tables from Phases 3-4 exist in `schema.prisma` with no migration at all, so `prisma migrate deploy` cannot reproduce the database in CI.

Purpose: Phase 6 adds 10 tables holding invoice amounts, payment records and Razorpay credentials. Cross-tenant leakage of that data is the highest-severity failure available in this product. This plan closes the isolation boundary first.
Output: a pooled, transaction-scoped tenant client; a baseline migration covering the whole current schema; RLS policies on every clinic-scoped table; a cross-tenant integration test that fails against the old implementation.
</objective>
