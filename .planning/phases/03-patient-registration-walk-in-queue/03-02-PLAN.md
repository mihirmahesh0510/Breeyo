    **2. Create `apps/api/src/modules/patient/patient.repository.ts`:**

    Class `PatientRepository` with constructor accepting PrismaClient:

    - `createOwner(params: RegisterOwnerParams)`: Uses `prisma.owner.upsert()` with where `{ clinicId_mobile: { clinicId, mobile } }`, create with all fields, update with nothing (return existing). This implements D-06: if mobile exists, return existing owner.

    - `findOwnerByMobile(clinicId: string, mobile: string)`: `prisma.owner.findUnique({ where: { clinicId_mobile: { clinicId, mobile } }, include: { pets: true } })`.

    - `createPet(params: RegisterPetParams)`: `prisma.pet.create({ data: { clinicId, ownerId, name, species, ...optionalFields } })`.

    - `findPetWithOwner(clinicId: string, petId: string)`: `prisma.pet.findFirst({ where: { id: petId, clinicId }, include: { owner: true } })`.

    - `getPetProfile(clinicId: string, petId: string)`: Find pet with owner, then separately query QueueEntry for visit history: `prisma.queueEntry.findMany({ where: { clinicId, petId, OR: [{ status: 'DONE' }, { status: 'NO_SHOW' }] }, orderBy: { checkedInAt: 'desc' }, take: 50 })`. Combine into profile response. This scopes to current clinic only per D-29.

    - `updatePet(params: UpdatePetParams)`: `prisma.pet.update({ where: { id: petId }, data: { ...fields } })`. Does NOT include ownerId in the update data.

    - `searchPatients(params: SearchParams)`: Uses `prisma.$queryRaw` with pg_trgm:
      ```sql
      SELECT DISTINCT ON (o.id)
        o.id as "ownerId", o.name as "ownerName", o.mobile,
        p.id as "petId", p.name as "petName", p.species,
        GREATEST(
          similarity(o.name, $query),
          similarity(o.mobile, $query),
          similarity(p.name, $query)
        ) as relevance
      FROM "Owner" o
      LEFT JOIN "Pet" p ON p."ownerId" = o.id AND p."clinicId" = $clinicId
      WHERE o."clinicId" = $clinicId
        AND (
          o.name ILIKE $searchTerm
          OR o.mobile ILIKE $searchTerm
          OR p.name ILIKE $searchTerm
        )
      ORDER BY o.id, relevance DESC
      LIMIT $limit
      ```
      Note: Always include explicit `WHERE o."clinicId" = $clinicId` even with RLS, because `$queryRaw` bypasses the Prisma Client Extension (Pitfall 1 from RESEARCH.md).

    - `getRecentPatients(clinicId: string, limit: number)`: Returns pets with owners ordered by most recent QueueEntry.checkedInAt. Uses raw SQL or a subquery to find the last visit date per pet.
