    **apps/api/src/modules/auth/permission.service.ts:**
    Implement `PermissionService` class exactly as in RESEARCH.md Pattern 4 with Redis caching:
    - Constructor: accepts PrismaClient (base) and ioredis client
    - `getUserPermissions(userId: string, clinicId: string): Promise<string[]>`:
      1. Check Redis cache key `perms:${userId}:${clinicId}`. If found, return parsed array.
      2. Query ClinicMember where userId + clinicId + isActive=true, include role -> rolePermissions -> permission.
      3. Collect default permissions from all roles into a Set<string>.
      4. Query UserPermissionOverride for this clinicMemberId, include permission.
      5. Apply overrides: if granted=true, add to set. If granted=false, delete from set.
      6. Cache result in Redis with 300-second (5 min) TTL: `await redis.setex('perms:${userId}:${clinicId}', 300, JSON.stringify(Array.from(finalPerms)))`.
      7. Return permission code array.
    - `invalidateCache(userId: string, clinicId: string)`: Delete Redis key `perms:${userId}:${clinicId}`. Called after any role/permission change.
    - `hasPermission(userId: string, clinicId: string, ...permissions: string[]): Promise<boolean>`: Get user permissions, check all are included.

    Export `requirePermission(...permissions: string[])` factory function that returns a Fastify preHandler:
    1. Read request.user.id and request.user.activeClinicId (set by authenticate middleware).
    2. Call permissionService.getUserPermissions(userId, clinicId).

    Add to **apps/api/src/modules/auth/auth.service.ts:**

    - `inviteStaff(input: { phone: string, fullName: string, roleName: RoleName }, clinicId: string, inviterId: string, ipAddress: string, userAgent: string)`:
      1. Find or create user by phone. If creating, set a temporary random password (user will set their own via SMS link). Set isActive=true, isEmailVerified=false, isPhoneVerified=false.
      2. Look up Role by name (roleName).
      3. Create ClinicMember for user in clinicId with roleId. Per D-15, a user can have multiple roles so don't error if member exists -- just add the role.
      4. Send SMS invite via OTP service (or separate invite SMS) with setup link.
      5. Write USER_INVITED audit event with targetUserId.
      6. Return { member: { id, userId, clinicId, role } }.

    - `updateMemberRoles(memberId: string, roleIds: string[], clinicId: string, adminId: string, ipAddress: string, userAgent: string)`:
      1. Verify member belongs to clinicId.
      2. Update clinic_member roleId (or if multiple roles supported, create additional clinic_member records with different roles).
      3. Invalidate permission cache for affected user.
      4. Write ROLE_ASSIGNED audit event.

    - `updateMemberPermissions(memberId: string, overrides: { permissionCode: string, granted: boolean }[], clinicId: string, adminId: string, ipAddress: string, userAgent: string)`:
      1. Find member, verify belongs to clinicId.
      2. For each override, find Permission by code. Upsert UserPermissionOverride for (clinicMemberId, permissionId) with granted value.
      3. Invalidate permission cache for affected user.
      4. Write PERMISSION_OVERRIDE audit event with details showing what changed.

    - `deactivateMember(memberId: string, clinicId: string, adminId: string, ipAddress: string, userAgent: string)`:
      1. Set clinic_member isActive=false.
      2. If user has no other active clinic memberships, set user.isActive=false (blocks login per D-17).
      3. Invalidate permission cache.
      4. Write USER_DEACTIVATED audit event.

    - `changePassword(userId: string, currentPassword: string, newPassword: string, ipAddress: string, userAgent: string)`:
      1. Find user by id. Verify currentPassword with argon2.verify.
      2. Hash newPassword with argon2.hash.
      3. Update user.passwordHash.
      4. Call tokenService.revokeAllUserTokens(userId) per D-21.
      5. Write PASSWORD_CHANGE audit event.
      6. Write SESSION_REVOKED audit event.
